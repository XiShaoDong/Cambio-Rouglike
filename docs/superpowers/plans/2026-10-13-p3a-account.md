# P3a：账号 / 身份（设备匿名）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`).
> 设计见 `docs/superpowers/specs/2026-10-13-p3-account-steam-design.md`（P3a 段）。分支 `agent/feature-online`。
> 原则：先方案→确认→再动代码；不改对局规则/快照牌面投影/`HiddenInfo`；一次只解决一个可验证问题。

**Goal:** 给玩家**持久账号**（跨会话/跨房间）：设备匿名注册、昵称、持久战绩；连接时把座位关联到账号。**不依赖 Steam**（P3b/P3c 另行，待 Steam 资源）。

**Architecture**
- **账号服务**（方案 A，独立 HTTP/JSON，Python 零依赖）：`server/account/account.py`；`register/login/set_name/get_profile`；**文件持久化**（JSON，原子写）。
- **客户端**：`AccountClient`（Godot `HTTPRequest`）+ 本地身份持久化 `user://account.cfg`（`account_id`+`secret`）；首启自动注册，之后登录。
- **关联**：连接握手带 `account_id`（+可选 secret），服务器存 `players[seat].account_id`（内部用，**默认不下发快照**）。
- 兼容：老客户端无账号仍可匿名加入（P2 行为不变）。

**Tech Stack:** Python 3（stdlib）+ Godot 4.6/GDScript。

## Global Constraints
- 不改对局规则/`match_snapshot` 牌面投影/`HiddenInfo`；座位仍 `seat_id`。
- 账号服务独立进程；只存"身份+战绩"，不接触牌局牌面。
- `steam_id`/`account_id` 默认**不下发**快照（隐私）。
- 与 P2 目录服务同风格（HTTP/JSON、限速、纯逻辑类可单测）。
