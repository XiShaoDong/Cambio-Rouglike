## 1. 目标

在现有「单局结算」基础上，引入**多回合系列赛**、**货币经济**、**局间商店盲拍**与**首批遗物**，并保持现有服务器权威、私有快照、贴牌时序三条架构不变量不变。

- 基础模式（`enable_relics = false`）必须始终可独立运行，不受任何遗物影响。
- 所有改动全部落在**服务器权威**侧；客户端只做投影与意图提交。
- 新界面（商店、系列赛进度、观战条等）优先建 **`.tscn` 场景实体**（沿用 `scenes/ui/settlement_page.tscn` + 脚本的模式，布局可在编辑器拖拽），不纯代码生成。

## 2. 术语

- **局（match）**：系列赛中的单独一把牌局，现有 `match_number` 表示。
- **把（series）**：X 局合起来的整场系列赛。
- **回合（turn）**：单个玩家的单次行动，沿用现有语义。
- **存活**：`health > 0`（health 复用为灵魂币，见 §4）。
- **出局/观战**：`health == 0` 的玩家，留在房间、不再参与后续局，仅收公开信息。

## 3. 系列赛生命周期

| 环节 | 规则 |
| --- | --- |
| 建房 | 房主在大厅设定 **X 局**（`run_state.match_limit`，默认 5，范围 2-10 待定） |
| 局间 | 本局结算展示 → **商店停靠**（§5，等全员购买/跳过）→ **自动开下一局**（Timer 衔接，客户端显示"即将开始下一局"） |
| 把末 | 赛满 X 局 **或** 存活数 `<= 1` → **直接进系列赛总排名**（不进商店）→ 房主可开新一把 |
| 中途加入 | **禁止**中途新玩家加入（断线重连除外）；观战者留在房间直至把末 |

**结束判定**（`game_state` 新增）：`match_number >= match_limit || _alive_count() <= 1` 时进入把末结算。

## 4. 货币经济

| 元素 | 规则 |
| --- | --- |
| 资源 | 开局每位玩家 **10 货币 + 1 灵魂币**。灵魂币复用 `health` 字段（1=活，0=出局） |
| 每局押注 | 所有**存活**玩家开局各押 **2 货币**进奖池；本局**胜者（们）平分奖池**（平局拆池，余数向下取整丢弃） |
| all-in | 货币 `< 2`（押不起）时，可选择 **all-in**：押上全部货币 + 灵魂币。**赢** = 保留灵魂币 + 赢回奖池继续；**输** = `health→0` 出局 |
| 出局 | 复用现有 `_is_alive`（`health > 0`）框架；观战者收公开信息、无操作权限 |
| 把末排名 | 存活者按 **单局胜场数降序 → 同胜场再按货币降序**；**淘汰者不入榜**（后续可加，改动仅限排名过滤函数） |

**记账字段**（扩展 `run_state` / `players[seat]`）：`currency`、`wins`、`match_limit`、`eliminated`（可复用 `health==0` 判定）。

**胜场统计**：`_finish_game` 结算处给 `winners` 累加 `wins`。

## 5. 商店盲拍（每局结算后，把末除外）

| 元素 | 规则 |
| --- | --- |
| 展示 | **3 件随机遗物**（从已批准遗物池抽取），各带**起拍价**（默认 2 货币） |
| 出价 | 每位玩家**限选 1 件**，输入出价（用**货币**）；可见每件"当前有几人选择"的**数量**，**不可见金额** |
| 揭示 | **每位存活玩家均已提交（出价或跳过）** → 统一同时揭示；若**全员跳过**则不开拍，直接进下一局 |
| 成交 | 每件**价高者得**：扣货币、获得遗物；同价并列 → **先到先得**（服务器接收出价顺序） |
| 败者 | **本轮失去购买资格**（鼓励分散选不同遗物） |
| 跳过 | 允许跳过本商店；全员跳过则提前进入下一局 |
| 持有 | 遗物**不设上限**；同种遗物重复获得 = **后者替代前者**（`relics` 为 Dictionary，同 id 覆盖） |

**协议**（新增 RPC）：`request_bid`（遗物 id + 出价）、`request_skip`；商店快照含每件遗物的"已选人数"（不含金额）。

## 6. 遗物 v1（首批两件，均需填写遗物设计卡）

| 遗物 | 触发时机 | 效果 | 代价/边界 |
| --- | --- | --- | --- |
| **Joker 变换** | **抽牌阶段（抽牌堆或弃牌堆顶取到）Joker** 时 | 可选把这张 Joker 变换成**任意一张牌**（点数+花色），随后按正常抽牌流程处理 | 未变换时 Joker 分值按 **+2** 计（原 0 分）；效果持整把，每局均可触发 |
| **防守护盾** | **购买后下一局生效** | 随机保护你**一个格子**，该格**免疫其他玩家的贴牌与交换** | 看牌（peek）不受影响；自己对自己的操作不受影响；**一局后失效** |

### 6.1 事件钩子机制（新增）

为支持遗物，新增**服务器侧事件钩子**（扩展 `RunModifier` 或 `effect_system` 的钩子入口）：

- `on_draw_joker`（抽到 Joker 时，Joker 变换）
- `on_match_start`（局开始时，防守护盾随机选格）
- `before_score`（结算评分时，预留）

钩子输入为**事件上下文副本**；钩子只能返回合法规则变化。不把隐藏牌信息下放客户端。`enable_relics = false` 时钩子不生效。

## 7. 架构落点（全服务器权威）

| 组件 | 落点 |
| --- | --- |
| 系列赛判定 + 把末结算 | `game_state.gd` |
| 系列赛排名函数 | 独立纯函数（不并入 `ScoreSystem`） |
| 货币记账 / all-in / 押注 / 奖池 | `game_state.gd`（`_finish_game` 扩展） |
| 商店 Phase + 快照 + RPC | 新 Phase 值 + `game_state.gd` 商店子模块（或独立 `shop_system.gd`） |
| 遗物钩子 | `RunModifier` 扩展 / `effect_system.gd` 钩子入口 |
| 观战视角 | `hidden_info.gd`（公开信息视角，无手牌） |
| 客户端 UI（场景实体） | 大厅 X 配置、结算页系列进度/总榜、商店页（`.tscn`）、护盾标记、观战条 |
