# P2：中心房间服务 + 随机短码（Room Directory）设计 v1

> **目的**：让联机从"输 IP:端口"变成"**建房拿码、输码加入**"。核心是一个**中心目录服务（Directory）**：登记房间 → 分配**随机短码** → 客户端凭码查地址并连接。房间生命周期（空房回收、房主转移、码 TTL）在此定义。
> **前置**：P1 已完成（中立专用服务器 headless、不占座、abort/close 语义）；L1 大厅已完成（两态、槽位、Ready、房主控制）。
> **权威不变**：规则/状态机/对局快照牌面投影/`HiddenInfo` 不动；本设计只加"房间目录 + 客户端接入 + 生命周期"。

## 1. 目标与非目标

**目标**
1. **随机短码建房/加入**：建房 → 得短码（如 `K7X2Q9`）→ 分享 → 他人输码加入。
2. **中心目录服务**：短码 ↔ 房间地址（`host`/`port`）登记与查询；短码唯一、可回收。
3. **房间生命周期**：空房回收、码 TTL、房主离开转移、断线重连；**杜绝 zombie**。
4. **两种宿主模式兼容**：
   - **dedicated（推荐）**：VPS 上专用服务器启动即向目录登记（其公网地址）；码 → 服务器地址。
   - **player-host**：房主进程向目录登记其**公网可达**地址（需公网 IP/端口转发；否则不可用）。
5. 多房并发（同一中心目录登记多间房；dedicated 可一进程多房或一房一进程，见 §7）。

**非目标**
- 不做 NAT 穿透/中继/SDR（player-host 若在 NAT 后需自行解决可达性；后续再谈）。
- 不做账号/Steam/ranked（P3/P4）。
- 不改对局规则/快照。

## 2. 现状（出发点）
- 客户端 `Network.join_game(address, profile, port)` 直连；大厅"加入房间"填 IP。
- 服务器权威 `GameState`；seat 身份 + token 重连；`host_seat` 动态房主（P1/L1 已就绪）。
- 已有 `ServerMain`（`scenes/server.tscn`）可 headless 起专用服务器。

## 3. 架构

```
 玩家A(建/房主)                      玩家B(加入)
      │  create(addr)                    │ join(code)
      ▼                                  ▼
  ┌────────────── 中心目录服务 Directory ──────────────┐
  │  code → {host, port, mode, players, heartbeat, ttl}│
  │  * 唯一短码分配、查询、心跳、回收、限速(防枚举)      │
  └───────────────────────────────────────────────────┘
      │ 登记 addr(code)                    │ 返回 addr
      ▼                                    ▼
   房间(专用服务器 或 玩家-host)  ◀── ENet 直连 ──  玩家B
```

### 3.1 目录服务（Directory）
- **always-on**、公网可达（VPS 上另起一个进程/端口）。
- 职责：分配/回收短码、`code→地址` 映射、心跳、TTL、限速。
- **不参与游戏逻辑**（纯登记/查询）。

### 3.2 建房（注册）
- 宿主（dedicated 服务器 或 玩家-host 房主）启动时：
  1. 调目录 `create_room({host, port, mode, max_players})` → 得 `code`。
  2. 周期性 `heartbeat(code)`（如每 10s）续命。
  3. 房间关闭时 `close_room(code)`（主动回收）。
- 宿主把 `code` 展示给房主/所有成员（"房间码 + 复制"）。

### 3.3 加入（查码连接）
- 客户端主菜单"加入房间"输入 `code` → 调目录 `join_room(code)`：
  - 命中 → 返回 `{host, port}` → 客户端 `Network.join_game(host, port)`。
  - 未命中/过期 → 提示"房间不存在或已过期"。
- （可选）`list_rooms()` 列出公开房（本期可选）。

### 3.4 心跳与生命周期
- 宿主心跳续命；目录在**连续 N 次无心跳**（如 30s）后标记房间失效并回收码。
- 空房（0 玩家）→ 宿主侧（客户端数）判断；dedicated 房间对象在 0 人满 TTL 后自毁（见 §6）。

## 4. 目录协议（草案）
> 传输二选一（见 §7）：**HTTP/JSON**（推荐）或 **ENet 自定义请求**。字段与语义一致。

| 请求 | 载荷 | 响应 | 说明 |
| --- | --- | --- | --- |
| `create_room` | `{host, port, mode: "dedicated"\|"player_host", max_players}` | `{code, expires_in}` | 分配唯一码；`host/port` 为可直连地址 |
| `heartbeat` | `{code}` | `{ok}` | 续命；房间不存在 → `{ok:false, err:"expired"}` |
| `close_room` | `{code}` | `{ok}` | 主动回收 |
| `join_room` | `{code}` | `{host, port, mode}` 或 `{err}` | 查地址 |
| `list_rooms`（可选） | `{}` | `[{code, mode, players, max_players}]` | 公开房列表 |

错误码：`ROOM_NOT_FOUND` / `ROOM_EXPIRED` / `RATE_LIMITED` / `BAD_REQUEST`。

## 5. 短码

| 项 | 约定 |
| --- | --- |
| 字符集 | Crockford base32（`0123456789ABCDEFGHJKMNPQRSTVWXYZ`，去 `I/L/O/U`，防混淆） |
| 长度 | **6 位**（≈ 2⁵⁰·… / 约 10⁹ 量级组合，配合限速足够） |
| TTL | **30 分钟**（**仅限制"用码加入"**；与断线重连无关，见 §6） |
| 唯一性 | 目录内活跃码唯一；分配时碰撞重试 |
| 防枚举 | 按 IP 限速（如 10 次/分钟）；失败不区分"不存在/过期"（统一提示） |

## 6. 房间生命周期（拍板沿用）
- **码 TTL 30min**（只影响"用码加入"）≠ **房间存活**（有无玩家）≠ **断线重连**（用 `token`，与码无关）。
- **空房回收 60s**（0 在线玩家满 60s → 销毁房间/回收码）。
- **房主离开 → 转移**给下一在线玩家（仅 LOBBY；对局中掉线走"暂停+重连"，已实现）。
- **解散/中止** = 销毁/重置房间（dedicated 保留进程、无 zombie，已实现 `_end_room`）。
- 宿主进程崩溃 → 目录靠**心跳超时**回收码（防残留）。

## 7. 目录服务实现选型（待定，建议）
| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| **A. 独立轻服务（HTTP/JSON，Python/Go）** | 极简、`curl` 可调、语言无关、易部署/重启 | 多一个工具链/进程 |
| **B. Godot headless 目录（ENet 自定义）** | 单一技术栈、复用 `Network` | 为请求/响应硬套 ENet、调试不便；仍需常驻进程 |
> **建议 A**：目录是"查表 + TTL"的琐碎服务，HTTP 最省事；游戏流量仍走 ENet 直连。若坚持单栈则用 B。

## 8. 与 P1 的关系
- **dedicated**：`ServerMain` 启动 → 向目录 `create_room`（其**公网**地址，需配置/自动探测）→ 打印/暴露 `code`；进程退出/解散 → `close_room`。
  - 多房：见 P2c——可"一房一进程"（简单）或"一进程多房 + 目录按 room 维度登记"（复杂，后置）。
- **player-host**：房主进程向目录登记**其公网可达**地址（否则他人连不上）→ 与 P1 的"玩家-host 模式保留"一致。

## 9. 部署（参数待填，届时你提供 VPS 信息）
- VPS 上运行：**目录服务**（新端口，如 UDP/TCP 7010/7011）+ **专用服务器**（UDP 7007）。
- 两层防火墙放行相应端口（云 Security List + 系统 ufw/iptables）。
- 客户端**唯一需要配置**的是"目录地址"（写死或客户端设置项）；房间连接不再需要玩家知道 IP。
- 待填参数：实例架构（x86_64/ARM）、OS 版本、公网 IP、域名(可选)、端口、SSH 方式。

## 10. 客户端改动
- 主菜单"加入房间"：输入**房间码** → 目录 `join_room` → `Network.join_game`。
- 建房/宿主：`code` 显示 + 复制（复用现有"房间地址/复制"位，改为**房间码**）。
- 设置项：**目录服务地址**（默认指向你的 VPS）。
- 已完成的 L1 大厅（两态/槽位/Ready/房主控制）直接复用。

## 11. 隐私与安全
- 目录会暴露房间的 `host:port`（玩家 IP）。若要隐藏 IP，需中继（非目标，后续）。
- 码枚举防护（限速 + 足够长度 + 失败统一响应）。
- 目录不接触牌局数据；不存玩家隐私。

## 12. 分期
- **P2a 目录服务 MVP**：`create_room`/`join_room`/`heartbeat`/`close_room` + 码分配/TTL/限速（本地 + 单元测试，HTTP 或 ENet）。
- **P2b 生命周期**：心跳超时回收、空房 60s、码 TTL、房主转移（复用 L1）。
- **P2c 客户端接入**：输码加入、建房显码、设置目录地址；dedicated `ServerMain` 自动登记。
- **P2d（可选）**：多房并发/房间列表/一进程多房。

## 13. 测试
- 目录纯逻辑单测：码唯一/碰撞、TTL 过期、限速、心跳回收、`join` 命中/失效。
- 客户端接入单测：输码 → 得到地址 → 连接（可用假目录）。
- E2E（本地）：起目录 + 专用服务器 + 两个客户端，用码加入并开一局。
- 回归：P1/L1 + 既有全量。

## 14. 非目标
- NAT 穿透/中继、账号/Steam、ranked、跨平台、多房编排的最优形态。
