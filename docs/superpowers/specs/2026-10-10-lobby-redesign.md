# 大厅重设计（Lobby Redesign · Ready / 槽位 / 房主控制 / 随机短码）设计 v1

> **目的**：把当前"一屏调试面板"式大厅，改造成常规游戏大厅：**创建/加入分流 → 房间界面（房间码 + 固定槽位 + 每人 Ready + 房主控制 + 设置全员可见）→ 开局**。房间加入最终走 **随机短码**。
> **权威不变**：规则/状态机/快照投影/`HiddenInfo` 不动；本设计只在**大厅阶段**加**服务器权威**的座位状态（ready）与房间控制。房主沿用 **seat 0** 概念（见 `feature-online P1`）。
> **与在线路线图关系**：本设计分两阶段——**L1 大厅 UX（可独立先做，无需中心服务）** 与 **L2 随机短码（= 在线路线图 P2：需要"中心房间目录"服务）**。

## 1. 目标与非目标

**目标**
1. **两态大厅**：主菜单态（创建 / 加入）+ 房间态（码 / 槽位 / Ready / 房主控制 / 设置）。
2. **固定槽位**：渲染 `0..MAX_PLAYERS-1` 个座位，空位显示"等待加入"，而非只列已加入者。
3. **Ready（服务器权威）**：非房主可切换"准备"；房主开局可选择"需全员 ready"。
4. **房主控制**：开始、**在线踢人**、解散/退出、设置（局数）对**所有成员可见**。
5. **随机短码加入**：房主/服务器建房间后得到短码（如 `K7X2Q9`），其他人输码加入（L2，需中心目录）。
6. 保留现有 `seat_id` 身份、token 重连、`Phase` 语义、LAN 玩家-host 模式。

**非目标**
- 不改规则/状态机/快照牌面投影/`HiddenInfo`。
- 不做账号系统/MMR/排行榜（属在线 P3/P4）。
- L1 不要求中心服务；L2 才引入中心目录。

## 2. 现状问题（对照 `scripts/ui/lobby_view.gd`）
1. 无"创建/加入"分流：昵称 + 房主 IP + 端口 + 3 按钮挤一屏。
2. 无房间码，加入要手打 `IP:端口`。
3. 无 Ready 状态，房主只能硬开始。
4. 只列"已加入者"，无固定槽位/空位。
5. 房主设置（`match_limit_spin`，`lobby_view.gd:161/175`）仅房主可见。
6. 无在线踢人 / 房主转移（仅有 `request_kick_offline`）。

## 3. 目标 UX

### 3.1 主菜单态
- 昵称输入。
- 两个主按钮：**创建房间** / **加入房间**。
- 加入房间：**输入房间码**（L2 随机码；L1 暂用直连信息 `IP:端口`）。
- 折叠的"高级/直连"（可选）：直接填 `IP:端口`（开发/局域网用）。

### 3.2 房间态
- 顶部：**房间码**（大号、可点击 **复制**；L1 显示直连信息）。
- 中部：**固定槽位列表**（空位="等待加入…"）；每行显示昵称 +（房主标） + Ready 标记。
- 底部：
  - 非房主：**准备 / 取消准备** 按钮 + **退出房间**。
  - 房主：**开始对局**（满足人数 **且全员 Ready** 才可点）+ **局数设置** + **踢出**（每行）+ **解散房间**。
- 设置（局数等）对所有人**只读可见**，对房主可编辑。

## 4. 架构与权威（关键，防返工）

1. **Ready 是服务器权威状态**：存 `players[seat].ready`，随 **lobby 快照**下发；客户端只发 `request_set_ready(bool)`。**禁止纯客户端 ready**。
2. **房主 = 房间创建者 = 首个进入的玩家**，存为**动态 `host_seat`**（默认 0）。**房主离开→转移**给 `turn_order` 下一个在线玩家（**仅 LOBBY 生效**；对局中掉线走"暂停+重连"）。所有房主校验读 `host_seat`（不再写死 0）。dedicated 后房主是 **seat `host_seat` 客户端**，不是服务器进程（见 `feature-online P1`）。
3. **槽位 = 座位 0..MAX-1**：空/离线座位照常渲染占位；`turn_order` 仍是权威。
4. **Ready 不改变座位**：加入即入座（现状不变），ready 仅状态。
5. **随机短码（L2）**：由**中心房间目录**下发/登记——
   - `create_room`：中心分配唯一短码 → 绑定该房间地址（玩家-host 的 `IP:端口` 或 dedicated 服务器地址）。
   - `join_room(code)`：中心查码 → 返回地址 → 客户端连接。
   - 码生成需防碰撞（唯一性）与防枚举（限频/长度足够，如 6 位 base32 ≈ 10⁹ 空间，加短 TTL + 限速）。
   - **纯随机短码无法离开中心目录**；无中心服务时只能用直连码（L1）。
6. **L1/L2 解耦**：L1 只改客户端大厅 UI + 服务器权威 ready/踢人；L2 才接入中心目录与随机码。
7. **生命周期与时限（2026-10-10 拍板）**：
   - **开始对局必须全员 Ready**；每局结束后 ready **重置**。
   - **断线重连宽限 60s**。
   - **短码 TTL 30 分钟**（**仅限制"用码加入"**）；**空房回收 60s**（多房，P2）。
   - **三者独立**（勿混淆）：**码 TTL**（还能否用码加入）≠ **房间存活**（有无玩家）≠ **断线重连**（用 `token`，与码无关）。
     - ⇒ **码过期不会导致掉线连不回来**；只要房间还在（未因 0 人回收）就能凭 token 回座。
     - ⇒ 只要房间内还有任意一人在线，房间一直存活（码过期也不影响在场玩家）。
   - **解散 = 销毁/重置房间资源**（不做"只踢人、房间留着"，杜绝 zombie）。

## 5. 数据与协议

### 5.1 lobby 快照新增字段（只读）
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `players[].ready` | bool | 每人准备状态（服务器权威） |
| `your_id` | int | **逐 peer** 下发："你是几号座位"（用于客户端判房主/自己行） |
| `room_host` | int | 房主座位（**动态 `host_seat`**，默认 0；房主转移后变化） |
| `room_code` | String | 房间码（L2 由目录下发；L1 为空/直连信息） |
| `dedicated` | bool | 是否专用服务器（影响房主任职与按钮语义） |
| `max_players` | int | 已有；用于渲染空槽 |

> 原则：**只读附加**，不改既有字段语义；不写入对局快照（`match_snapshot`）。

### 5.2 新增请求（体现层/大厅层，不碰对局规则）
| 请求 | 方向 | 校验 |
| --- | --- | --- |
| `request_set_ready(on)` | client→server | 仅 LOBBY；写 `players[seat].ready`；广播 lobby |
| `request_kick(seat)` | client→server | 仅 LOBBY、**sender == host_seat（房主）**、目标非房主；断开该 peer + 移除座位 |
| `request_start_match(limit)` | 已有 | 仅房主（`sender == host_seat`）；**必须全员 ready** 才可开 |
| `request_room_code()` / 目录客户端 | client→server(目录) | **L2**；生成/查询短码 |

## 6. 两个阶段 + 与在线路线图关系

| 阶段 | 内容 | 需要中心服务 | 对应在线 P |
| --- | --- | --- | --- |
| **L1 大厅 UX** | 两态、固定槽位、Ready、房主控制（开始/踢在线/设置可见）、复制直连信息 | ❌ | 可独立先做 |

（L1 可在 P1 之前/并行先做；L2 与 P2 合并。）

## 8. 测试与验收（L1）
- ready：`_apply/._server_set_ready` 写座位并广播；非 LOBBY 拒绝；离线者不可 ready。
- 踢在线：非房主 → `NOT_HOST`；踢房主 → 拒绝；踢后快照座位消失。
- 开局门槛：未全员 ready → 拒绝（**必须全员 ready**）；全 ready → 可开；开一局后 ready 重置为 false。
- 房主转移：房主离开（LOBBY）→ `host_seat` 转移到下一在线玩家；房主校验随之生效（原房主失去权限）。
- 槽位：`max_players=4`、只 2 人时渲染 2 空槽。
- `your_id`：每个接收者拿到自己座位；`your_id == host_seat` 端 `is_room_host==true`。
- 回归：`verify_reconnect`/`verify_protocol`/`verify_series`/`verify_restart` + 3D/UI 全量绿。
- **双模式**：LAN 玩家-host 行为不变；dedicated（P1）下同样成立。

## 9. 风险与坑
- Ready/host **必须服务器权威**，别做客户端本地。
- 沿用 **seat 身份**，别用 peer。
- **别把"房主=服务器进程"或"房主=座位0"写死**：房主 = 动态 `host_seat`；dedicated 后是某个客户端（与 P1 对齐）。
- 随机短码的**防枚举/防碰撞/TTL**：码要够长 + 限速 + 过期回收，否则会被扫。
- `your_id` 逐 peer 下发要跳过离线（peer<=0），避免广播泄漏/浪费。
- 大厅字段**不进对局快照**，避免污染 `state_revision` 去重。
