# P4：Ranked 匹配 + 组队（Matchmaking & MMR）设计 v1

> **目的**（**最终目标**）：排位匹配（按 MMR 找对手）、组队排队、权威结算与段位。让玩家不靠"手动房间码"也能开局上分。
> **前置**：P2（中心目录/房间服务）、P3a（持久账号 `account_id` + `stats`）。权威仍在你的 VPS。
> **现状**：已有账号服务（`server/account`）、目录服务（`server/directory`）、中立专用服务器（P1）、房间码（P2）。缺：段位数据、队列、组队、权威结果上报。

## 1. 目标与非目标

**目标**
1. **MMR**：每个账号一个评分；对局结束后按名次更新（多人 Elo）。
2. **匹配队列**：solo / 组队 入队 → 凑齐人数 → 分配一个房间（专用服务器 + 房间码）→ 各端加入。
3. **组队（Party）**：玩家组成 party（队长 + 成员），整队排队。
4. **权威结算**：对局结束由**服务器**上报名次 → 匹配/账号服务更新 MMR（玩家不可自报）。
5. **段位显示**：MMR → 段位（如 Bronze/Silver/…）。

**非目标**
- 反作弊加固（P5）；跨平台；赛季周期/奖励（可后置）。

## 2. 架构

```
玩家(solo/party) ──enqueue──▶ 匹配服务（中心）──分组──▶ 分配房间(专用服务器+码)
      ▲                                              │
      └──────────── MMR/段位 查询（账号服务） ◀──结算上报(服务器权威)──┘
```

- **匹配服务**（中心，独立 HTTP/JSON，`server/matchmaking`）：队列、分组、房间分配、结果上报。
- **账号服务扩展**（`server/account`）：`account.mmr`、`rank`；`report_result` 更新。
- **专用服务器**：被匹配分配后开一局；结束时向匹配服务**上报名次**。

### 2.1 MMR（多人 Elo，按名次）
- 每账号 `mmr`（初始 1000）。4 人一局按名次两两比较（或"名次 → 期望得分"）。
- 简化：用**名次得分** `S_i = (N - place_i)/(N-1)`（第一=1，垫底=0），与 Elo 期望 `E_i` 比较，`Δ = K*(S_i - E_i)`。
- `K`（如 32）；并列名次取平均得分。可替换为 Glicko/TrueSkill（后置）。

### 2.2 队列与匹配
- 入队（solo 或 party）携带各成员 `mmr`；匹配服务按 MMR 邻近 + 等待时长成组（如 4 人一房）。
- 成组 → **分配房间**：向目标专用服务器（池中一台）登记一局 → 得到**房间码**（复用 P2 目录）→ 推给各端 → 各端 `Network.join_game`。
- 分配策略：先"单机多房"或"一局一进程"（P2d 范畴，可先用"固定服务器 + 房间码"）。

### 2.3 组队（Party）
- Party = `{party_id, leader, members[]}`，由匹配服务或账号服务维护。
- **本期不依赖 Steam**：游戏内组队（队长建房/拉人，或从最近队友加入）。P3c 到位后用 Steam 好友组队。
- 整队以"平均 MMR"入队。

### 2.4 权威结算
- 服务器在某局 `GAME_OVER` 时，把 `{room, ranked:true, ranking:[account_id...]}` 上报匹配/账号服务（**服务器→服务，不经玩家**）。
- 服务按名次更新各账号 MMR；返回/记录新模式。
- 防作弊依赖：服务器权威（已有）+ 只接受来自**受信服务器**的上报（共享密钥/来源校验）。

## 3. 协议（中心服务，HTTP/JSON）
| 请求 | 载荷 | 响应 |
| --- | --- | --- |
| `POST /enqueue` | `{party:[account_id...], mode:"ranked"}` | `{ticket}` 或 `{status:"queued"}` |
| `POST /dequeue` | `{ticket}` | `{ok}` |
| `GET /status` | `?ticket=...` | `{state:"queued"\|"matched", room:{host,port,code}}` |
| `POST /report_result` | `{secret, room, ranking:[account_id...]}` | `{ok, deltas}` |
| `GET /profile`（账号服务） | `?account_id=` | `{mmr, rank, ...}` |

- 受信上报：匹配服务校验 `secret`（部署时配置，**环境变量**）。
- MMR 更新在**服务端**完成（客户端只收结果）。

## 4. 数据与落盘
- 账号服务：`account.mmr`（int，默认 1000）、衍生 `rank`（阈值映射）。
- 匹配服务：内存队列（短时）；结果上报后写回账号服务（持久）。

## 5. 分期
- **P4a 结算 + MMR**：账号服务加 `mmr`/`rank`；`report_result`（受信）+ 多人 Elo 更新；单测。
- **P4b 排队 + 匹配 + 房间分配**：`enqueue/dequeue/status`；成组→分配房间码（复用 P2）；可在**单机**用假服务器端到端测。
- **P4c 组队（Party）**：游戏内 party（不依赖 Steam）；整队排队。
- **P4d 段位显示/赛季**（UI + 阈值）。

## 6. 测试
- 服务端：MMR 更新（名次/并列/K）、`report_result` 受信校验、队列分组（MMR 邻近）、单测。
- 端到端（本机，无 Steam）：两个客户端账号 → 入队 → 匹配 → 收到房间码 → 加入 → 开一局 → 上报 → MMR 变化。可用**假专用服务器/或真 server.tscn**。
- 回归：P1/P2/P3 + 既有全量不变。
