# KONG 网络协议 V1

> **本文档职责**：客户端/服务器**协议契约权威**（RPC/快照字段、错误码、隐私、幂等）。开发实现见 `功能实现文档.md`；规则见 `KONG_开发文档.md`。改动协议字段前必须先更新本文档。

状态：**MVP 目标契约，待原型验证后逐项对齐**  
传输：Godot High-Level Multiplayer / ENet / UDP，可靠有序 RPC  
权威：房主服务器（LAN）或 Headless 服务器（VPS）  
关联主规格：[KONG 开发文档](KONG_开发文档.md)

本文定义客户端与规则服务器之间的接口，而非 UI 内部事件。任何新增 RPC、字段或规则必须先更新本文并提升 `protocol_version`（不兼容）或文档修订号（兼容）。

> **分支 `feature/3d-table` 说明**：3D 对局视图为纯客户端展示层，**未新增/修改任何 RPC、快照字段、错误码或幂等语义**；它消费与 2D 完全相同的 `match_snapshot`（含 `players[].slots` / `discard` / `pending` / `ready_count` / `q_decision` / `run` 等）。后续 3D 若需新字段，仍须先更新本文档。
> **更新**：后续"3D 角色"里程碑新增了快照字段 `players[].color`（玩家配色）与 `look` 注视 RPC（§3 / §4.8），均纯表现层、不入规则。

## 1. 协议状态与兼容规则

| 项目 | V1 要求 | 当前原型状态 |
| --- | --- | --- |
| `protocol_version` | 固定整数 `1`，加入大厅前双方必须相等 | 已实现：注册 RPC 携带版本，不匹配返回 `PROTOCOL_VERSION_MISMATCH` |
| `match_id` | 服务器建局时生成的不透明随机字符串 | 已实现：`_server_start_match` 生成并写入快照 |
| `state_revision` | 每次状态改变递增，客户端只接受更大的值 | 已实现：每次广播递增；客户端丢弃 `<=` 旧包 |
| `client_action_id` | 客户端每次命令生成 UUID；服务器按玩家去重 | 已实现：全部命令携带，每玩家保留最近 64 个，重复返回 `DUPLICATE_OR_EXPIRED_ACTION` |
| RPC 顺序 | 可靠、有序；服务器仍要按状态验证，不信任到达顺序 | 已采用 |

在 V1 完整对齐前，所有 LAN 客户端必须来自同一项目构建版本。版本不匹配时服务器返回 `PROTOCOL_VERSION_MISMATCH`，客户端不得进入大厅。

## 2. 通用类型与约束

| 类型 | 格式 / 范围 | 说明 |
| --- | --- | --- |
| `PeerId` | 正整数 | ENet peer ID；LAN 房主服务器本地 ID 为 `1` |
| `SeatId` | 0 起始整数 | **玩家身份**（0..N-1，注册顺序分配）；`players`/`turn_order`/`current_player`/`viewer_id`/动画事件中的玩家字段一律用 `SeatId`。`PeerId` 仅是当前连接，掉线重连会变化，`SeatId` 跨连接稳定（VPS 场景同样适用） |
| `Slot` | 0 起始整数 | 玩家当前手牌数组中的位置；不得缓存为永久坐标 |
| `CardId` | 不透明随机字符串 | 只用于 UI 追踪位置；不能编码点数、花色或牌堆顺序 |
| `Rank` | `A`、`2`–`10`、`J`、`Q`、`K`、`JOKER` | 仅在公开/私有允许时发送 |
| `CardView` | `{id, rank, suit, value, label, bomb}` | 牌面可见时使用；`bomb` 为公开炸弹标记（不泄露牌面） |
| `HiddenSlot` | `{card_id, bomb}` | 牌面未知时使用；不得有 `rank/suit/value`；`bomb` 可为 `true`（公开炸弹标记） |
| `Phase` | `LOBBY`、`INITIAL_PEEK`、`TURN_DRAW`、`TURN_DECISION`、`Q_DECISION`、`SLAP_WINDOW`、`SLAP_EXCHANGE`、`GAME_OVER`、`SLAP_DUEL`、`BET`（已弃用，不进入）、`SHOP`、`EFFECT_PASS`、`EFFECT_REVEAL` | 枚举名称是契约；数字仅为当前实现细节（`BET`=9、`SHOP`=10、`EFFECT_PASS`=11、`EFFECT_REVEAL`=12） |

所有昵称必须去除首尾空白、限制为 1–16 个可见字符。客户端输入仅用于显示；服务器可进一步过滤不安全字符。

## 3. 请求方向：客户端 → 权威服务器

在 Godot 中，以下行为可以表现为对应的 `server_*` RPC。每一项逻辑请求都应包含或由传输关联 `protocol_version`、`match_id`、`client_action_id`；表中只列业务载荷。

| 业务请求 | 业务载荷 | 合法阶段 | 服务端必须验证 |
| --- | --- | --- | --- |
| `register_player` | `{display_name}` | `LOBBY` | 协议版本、未注册、未满员；注册后服务器定向返回 `player_token` |
| `reconnect` | `{player_token, display_name}` | 任意（对局进行中） | token 有效、目标座位存在且离线、协议版本 |
| `start_match` | `{ match_limit: Integer }` | `LOBBY` | 调用者为房主、2–4 人；`match_limit` 为系列赛局数（2-10，越界回退默认 5；客户端可不传） |
| `initial_ready` | `{}` | `INITIAL_PEEK` | 调用者在本局且尚未确认；全员确认后服务器直接进入 `TURN_DRAW`（押注阶段已随 R-12 移除；若首回合抽到 Joker 增强则先进入 `EFFECT_PASS`） |
| `take` | `{source: "draw" | "discard"}` | `TURN_DRAW` | 调用者为当前玩家、来源可用；0 张手牌不得取弃牌顶 |
| `replace` | `{slot}` | `TURN_DECISION` | 当前玩家、槽位属于调用者、存在待处理牌 |
| `discard_draw` | `{}` | `TURN_DECISION` | 当前玩家、待处理牌来源为抽牌堆 |
| `use_ability` | 见下表 | `TURN_DECISION` | 当前玩家、待处理牌来自抽牌堆、牌面具有对应能力 |
| `q_decision` | `{exchange: bool, own_slot?: Slot}` | `Q_DECISION` | 当前玩家即 Q 操作者；换牌时 `own_slot` 合法 |
| `slap` | `{target_player: PeerId, slot: Slot}` | `TURN_DRAW`（且 `slap_open`） | 目标槽位存在 |
| `slap_duel_stop` | `{}` | `SLAP_DUEL` | 调用者为比拼候选人、未按过 STOP |
| `slap_exchange` | `{own_slot: Slot}` | `SLAP_EXCHANGE` | 调用者即贴中他人者、自己的槽位存在 |
| `kongbaya` | `{}` | `TURN_DRAW` | 调用者为当前玩家 |
| `set_match_limit` | `{limit: Integer, action_id}` | `LOBBY` | 房主专用；`limit` 夹到 2–10；成功后写 `run.match_limit` 并广播 lobby 快照 |
| `set_ready` | `{on: Boolean}` | `LOBBY` | **大厅准备（服务器权威）**：调用者已注册；写该座位 `players[].ready` 并广播大厅快照。非 LOBBY 忽略 |
| `set_effect_mode` | `{mode: String, effect_id: String, action_id}` | `LOBBY` | **房主设置效果模式（系列赛级）**：`mode ∈ normal/random/fixed`；`fixed` 时 `effect_id ∈ {six_swap,plus_one,bomb}`（none==普通，不作选项，否则 `INVALID_SETTING`）。写 `run.effect_mode/fixed_effect` 并广播 lobby 快照。非房主 `NOT_HOST`；非法参数 `INVALID_SETTING` |
| `set_shop_enabled` | `{on: Boolean, action_id}` | `LOBBY` | **房主开关系列赛商店**：写 `run.shop_enabled` 并广播 lobby 快照；关闭后非把末结算展示完毕直接开下一局（跳过 SHOP）。非房主 `NOT_HOST` |
| `back_to_lobby` | `{action_id}` | `GAME_OVER`（且把末） | **房主主动：全体回到等待房间（保留座位/连接，不广播 abort、不断开）**：重置对局与系列赛数据（wins/货币/生命/装备清零），`match_limit/effect_mode/fixed_effect/shop_enabled` 沿用；随后先广播 `room_reset`（客户端重置快照水位线），再广播 lobby 快照。非房主 `NOT_HOST`；非把末 `INVALID_PHASE` |
| `kick` | `{seat: SeatId}` | `LOBBY` | **房主踢出在线玩家**：调用者为房主（`host_seat`）、目标非房主；移除该座位并断开其连接（`NOT_HOST` 拒绝非房主） |
| `next_match` | `{}` | `GAME_OVER` | 调用者为房主（seat0）、人数 ≥ `MIN_PLAYERS`；成功后 `match_number += 1`、全员重发 `HAND_SIZE` 张、回 `INITIAL_PEEK`，快照 `result` 清空。**注**：把末（`_series_finished`）后调用被拒；非把末由服务器 Timer 自动触发，客户端无需手动调用 |
| `restart_match` | `{action_id}` | 非 LOBBY | 调用者为房主（seat0）、人数 ≥ `MIN_PLAYERS`；**重开本局**：生成新 `match_id`、全员重发 `HAND_SIZE` 张、回 `INITIAL_PEEK`；**保留** `match_number`/货币/生命/系列赛/`run_state`。非房主/LOBBY/人数不足 → 拒绝。客户端据 `match_id` 变化播开局发牌动画 |
| `shop_buy` | `{offer: Integer, action_id}` | `SHOP` | 存活玩家、尚未完成（限购 1 件）；`offer` 为自己货架索引（0/1）；越界/已拥有/遗物栏满 → `INVALID_OFFER`；货币 ≥ 该件固定价（不足 → `INVALID_AMOUNT`）；成功后扣款、进入个人遗物栏、清该槽锁并广播 |
| `shop_skip` | `{action_id}` | `SHOP` | 存活玩家、尚未完成；**结束商店**（跳过剩余遗物+道具卡，视为完成）；不清锁；全员完成 → 开下一局 |
| `shop_buy_card` | `{slot, action_id}` | `SHOP` | 存活玩家、尚未完成；slot 为自己 3 个卡位之一；每店限购 1 张、卡牌栏 <3、未重复持有（否则 `INVALID_OFFER`）；货币 ≥ $50（不足 `INVALID_AMOUNT`）；成功后扣款、入个人卡牌栏、清该槽锁 |
| `shop_card_refresh` | `{action_id}` | `SHOP` | 存活玩家、尚未完成；货币 ≥ $10；至少 1 个未锁卡位且卡牌栏未满（否则 `SHOP_REFRESH_UNAVAILABLE`）；成功后扣 10，只重掷未锁卡位 |
| `shop_card_lock` | `{slot, locked, action_id}` | `SHOP` | 存活玩家、尚未完成；slot ∈ 0..2 且卡位存在；写/清 `run_state.item_locks[seat][slot]`，免费、不改变 offer |
| `use_item_card` | `{slot, target_seat, action_id}` | `TURN_DRAW` / `TURN_DECISION` | 当前玩家、本回合未用过道具卡；slot 为个人卡牌栏索引；按卡 `target_mode` 校验 target（`next` 自动、`opponent` 需存活对手、`self` 自动、`none` 无）；成功后消耗并广播 `item_card_used`，不推进回合 |
| `shop_refresh` | `{action_id}` | `SHOP` | 存活玩家、尚未完成；货币 ≥ `SHOP_REFRESH_COST(10)`（不足 → `INVALID_AMOUNT`）；至少 1 个未锁货位且遗物栏未满（否则 → `SHOP_REFRESH_UNAVAILABLE`）；成功后扣 10，只重掷未锁货位 |
| `shop_lock` | `{slot: Integer, locked: Boolean, action_id}` | `SHOP` | 存活玩家、尚未完成；slot ∈ {0,1} 且货位存在（否则 `INVALID_SLOT`）；写/清 `run_state.shop_locks[seat][slot]`，免费、不改变 offer |
| `effect_power` | `{action_id}` | `TURN_DECISION` | 本局效果为 `six_swap`、调用者为当前玩家、`pending_draw` 为红 Joker 且来源为抽牌堆；成功后弃置红 Joker 并进入 `EFFECT_PASS` |
| `effect_pass` | `{slot: Slot, action_id}` | `EFFECT_PASS` | 调用者必须是快照 `effect_pass.await_seat`；`slot` 属于调用者且非空；成功后记录选择并推进队列，全部选完后一次性交换 |
| `joker_transform` | `{rank: String, suit: String, action_id}` | `TURN_DECISION` | 调用者为当前行动者、持有 Joker 变换遗物、`pending_draw` 牌面为 `JOKER`；`rank` ∈ A..K、`suit` ∈ ♠♥♣♦；成功后服务器把 pending 卡改 `rank/suit/value` 并广播（非 JOKER / 无遗物 → `ABILITY_FORBIDDEN`） |
| `look` | `{target: Vector3, zoom: Boolean, talking: Boolean, nose: Vector3}` | 任意（对局中） | **纯表现层，不参与规则**；仅校验发送者已注册（`_peer_to_seat`）；`target` 为世界注视点（相机射线固定距离处，须有限），`zoom`/`talking` 为放大/说话状态，`nose` 为鼻子指针**目标世界坐标**（hover 卡牌中心；`Vector3.ZERO`=未伸出；须有限，否则视作 ZERO）。无 `action_id`、不入快照 |
| `mark` | `{pos: Vector3, style: String, icon: String, text: String}` | 任意（对局中） | **纯表现层，桌面标记（按住 D 出轮盘选标）**；仅校验发送者已注册（`_peer_to_seat`）；`pos` 为落点世界坐标（须有限，否则忽略）；`style`∈ripple/nose、`icon`∈eye/question/number/exclaim、`text`（仅 number）。事件式转发给所有客户端、**不入快照**、无 `action_id` |
| `emote` | `{index: Integer}` | 任意（对局中） | **纯表现层，表情/动作（按住 Y 出轮盘选，0–5）**；仅校验发送者已注册（`_peer_to_seat`）。事件式转发给所有客户端、**不入快照**、无 `action_id`；为后续 avatar 真实动作预留 |

`use_ability` 的载荷：

| 抽到的牌 | 载荷 | 附加验证 |
| --- | --- | --- |
| 7 / 8 | `{slot}`；持有「视野互换」时可用 `{target, target_slot}` | 默认 `slot` 属于调用者；有视野互换时可指向其他玩家 |
| 9 / 10 | `{target, target_slot}`；持有「视野互换」时可用 `{slot}` | 默认 `target != 调用者`；有视野互换时可指向自己 |
| J | `{target, own_slot, target_slot}` | `target != 调用者`，双方槽位存在 |
| Q | `{target, target_slot}` | `target != 调用者`，目标槽位存在 |

服务器不得接受客户端提交 `CardId`、`Rank`、分值、洗牌结果、结算结果或计时结果作为规则依据。

## 4. 响应方向：权威服务器 → 客户端

### 4.1 大厅快照 `lobby_snapshot`

```text
{
  protocol_version: 1,
  lobby_revision: Integer,
  host_id: SeatId,      // 动态房主座位（= room_host；房间创建者/首个进入者）
  room_host: SeatId,    // 同 host_id（动态 host_seat）
  your_id: SeatId,      // 逐 peer 下发：接收者自己的座位（-1 表示未定）
  min_players: 2,
  max_players: 4,
  match_limit: Integer, // 系列赛局数（大厅只读展示；房主可改后开局）
  effect_mode: String,  // "normal"（无特效，默认）/ "random"（每局随机）/ "fixed"（整系列固定）
  fixed_effect: String, // fixed 模式下的特效 id（six_swap/plus_one/bomb；normal/random 下为 ""）
  shop_enabled: Boolean, // 系列赛商店开关（默认 true；false → 非把末结算直接开下一局不进 SHOP）
  players: [{ id: SeatId, name: String, ready: Boolean }]  // ready 为服务器权威的准备状态
}
```

此消息不能包含发牌随机种子、卡牌、匹配历史或任一玩家 IP。
- **逐 peer 下发**：同一房间不同接收者的 `your_id` 不同（用于客户端判"我是不是房主"= `your_id == room_host`）。
- **动态房主**：房主 = 房间创建者 = 首个进入者；房主离开（仅 LOBBY）→ 转移给下一在线玩家，`host_id`/`room_host` 随之变化（不再固定 0）。
- **ready**：非房主玩家的准备状态，由 `set_ready` 写入、服务器广播；用于房主开局门槛（客户端据此启用"开始对局"）。

### 4.2 对局快照 `match_snapshot`

每次权威状态发生可见变化时，服务器向每位已连接玩家发送一份独立快照。

```text
{
  protocol_version: 1,
  match_id: String,
  state_revision: Integer,
  phase: Phase,
  current_player: SeatId | null,
  current_name: String,
  viewer_id: SeatId,
  room_host: SeatId,               // 动态房主座位（只读；供客户端判房主 UI，如重开/踢人按钮）
  draw_count: Integer,
  discard: CardView | {},
  discard_count: Integer,          // 弃牌堆张数（客户端堆叠高度）
  discard_history: CardView[],     // 曾进入弃牌堆的牌（按时间顺序；公开信息，供 stats 面板）
  players: [{
    id: SeatId,
    name: String,
    color: String,  // 玩家机体配色（进入游戏随机分配、保证不重复，如 "#3ABA64"）
    count: Integer,
    health: Integer,  // 默认 2，垫底 −1，0 出局观战
    currency: Integer,
    eliminated: Boolean,
    relics: [String, String, String],  // 个人遗物栏固定 3 格；空槽 ""
    slots: (HiddenSlot | {card_id, card: CardView, bomb})[]  // bomb 公开
  }],
  pending?: CardView & { source: "draw" | "discard", granted_ability?: "peek_own" | "peek_other" },
  slap_rank: Rank,
  slap_open: Boolean,
  settle_deadline_server_ms: Integer,  // 最终轮结算贴牌窗口 deadline（服务器时钟 ms；0=不在窗口）。期间仅可贴牌，到时结算。
  effect_reveal_deadline_server_ms: Integer,  // 本局效果展示 deadline（服务器时钟 ms；0=不在展示）；仅 EFFECT_REVEAL 存在
  slap_duel?: { contestants: SeatId[], duration_ms: Integer, deadline_server_ms: Integer, target: Number },
  slap_exchange_actor?: SeatId,
  suspended: Boolean,
  offline_players: SeatId[],
  kong_caller?: SeatId,
  match_number: Integer,
  turn_index: Integer,             // 本局回合序号（每次换回合 +1；客户端据此只播一次增强动画）
  turn_effect: String,             // 本回合随机增强 id（服务器抽取 → 全员一致；已生效）
  effect_pass?: { queue: SeatId[], index: Integer, await_seat: SeatId, initiator: SeatId, clockwise: Boolean },  // 仅 EFFECT_PASS 存在；不泄露已选牌面
  run?: { match_limit: Integer, relics: {relic_id: {...}}, relic_inventories: {SeatId: [relic_id]} },  // shop_locks 服务器内部，不下发
  item_cards?: String[],       // 仅 viewer 本人：自己的道具卡 id 列表（私有）
  item_card_used?: Boolean,   // 仅 viewer：本回合是否已使用过道具卡
  shop?: {
    offers: [{index, id, name, price, locked}],
    card_offers: [{index, id, name, desc, price, target_mode, locked}],
    done: SeatId[], refresh_cost: Integer, can_refresh: Boolean,
    card_refresh_cost: Integer, card_can_refresh: Boolean,
    relic_bought: Boolean, card_bought: Boolean
  },
  shop_result?: { "<kind>_<seat>_<slot>": {relic_id|card_id, name, winner: SeatId, amount, slot, kind} },
  event_log: String[],
  result?: MatchResult
}
```

`player.id`/`current_player`/`viewer_id`/`slap_duel.contestants`/`slap_exchange_actor`/`kong_caller` 一律为 `SeatId`；客户端只比较这些字段是否相等（如 `player.id == viewer_id`），不依赖其绝对值对应网络 peer。

`suspended`：条件暂停标志（当前行动者离线 / 开局记忆阶段任一存活玩家离线）。`offline_players`：当前离线座位列表。二者为公开信息，客户端据此显示"对局暂停"与房主操作按钮（踢出/中止）。

`players[].health`：玩家当前生命（默认 **2**，每局垫底 −1，为 0 出局观战）。`players[].currency`：玩家当前货币（结算按名次发放，HUD 只读）。`players[].color`：玩家机体配色（`_add_player` 时从 `KongRules.PLAYER_COLORS` 随机取未占用色、保证不重复；纯展示，客户端用于给该席机器人上色）。`result.rewards`：仅结算存在，形如 `{ <SeatId>: { "money": Integer, "life_lost": Integer } }`（本局按名次发放给各座的金钱与扣减的生命数），客户端据此在结算页显示"本局奖励"；`result.penalized`：本局因垫底（含并列垫底）扣血者的 `SeatId` 列表（手牌超限 R-07、首回合 Kong 失败者按垫底处理，同样计入）。

`match_number` 是服务器只读的局数计数器（当前对局为第几局；MVP 单局固定为 1，多局模式递增）。只用于 UI 展示，客户端不得回传或依赖它做规则判断。

`turn_index` / `turn_effect`：每局随机增强（2026-10-16 起服务器权威，2026-10-20 起真实生效）。服务器在**每局开局发牌后**随机写入一次 `turn_effect`（`none`/`six_swap`/`plus_one`/`bomb`，不与上一局重复）并**保持整局不变**；开下一局（结算/商店后）重新抽取。**全员 Ready 后先进入 `EFFECT_REVEAL` 展示 5s，期间禁止操作，随后才进入第一个玩家的 `TURN_DRAW`**。`turn_index` 仍每次换回合 +1。客户端以 `match_id` + `turn_effect` 判断是否播放展示动画（**不得用 turn_index 判断**，否则每回合重播）。规则效果：
- `none`：无效果。
- `six_swap`：**打出任意花色的 6**（弃置手牌中的 6 / 弃掉抽到的 6）或**抽到红 Joker 并调用 `effect_power`**时进入 `EFFECT_PASS`；从打出者开始按顺时针依次让每名有手牌的存活玩家选一张自己的牌，全部选完后一次性传给下家（收到上家的牌放入自己刚才交出的槽位）。只触发该次打出，不是每回合自动触发。快照 `effect_pass.await_seat` 指当前等待者，只公开队列进度，不公开选择的牌面；离线玩家由服务器自动随机选择。
- `plus_one`：**每名玩家自己的回合开始**，仅该玩家的左下角槽位（`slot 2`）点数在 `A→2→…→Q→A` 循环中 +1；`K`/`JOKER` 不变。按槽位生效，换牌后新牌在下个自己的回合继续 +1。
- `bomb`：**开局发牌后**从抽牌堆随机选最多 4 张标记炸弹（不碰手牌，只标记一次）；炸弹牌在持有者自己的每个回合开始倒计时，3 回合后从手牌移除（移出对局，不进弃牌堆）。快照槽位与 `CardView` 的 `bomb` 为公开标记，不含牌面。

`run.match_limit`：系列赛局数 X（房主开局设定，2-10，默认 5），仅系列赛模式存在（`run` 可选字段）。`players[].eliminated`：出局观战标记（`health==0` 的玩家为 `true`，保留座位、仅公开信息、不可操作）。`result.series`：仅把末（`_series_finished`）存在，形如 `{ finished: Boolean, ranking: [{id, name, wins, currency}] }`（存活者按胜场数降序→同胜场按货币降序，淘汰者不入榜）；非把末不存在该字段。

`run.relics`：已出现的遗物定义目录（`relic_id → {id, name, desc, price, glyph, ...}`，展示用）。`run.relic_inventories`：每人独立遗物栏（`SeatId → [relic_id]`，最多 3 件；不同玩家可重复持有同一遗物，同一玩家不可重复）。`run.shop_locks`：每人商店锁（`SeatId → {slot: relic_id}`），跨刷新/商店保留；**服务器内部字段，不下发快照**（viewer 从自己的 `shop.offers[].locked` 得知锁定状态）。**遗物效果（M4）**：护盾遗物在下一局开局被消耗（随机护盾持有者一格，快照槽位带 `protected` 标记）；Joker 变换遗物使持有者抽到 Joker 时可调 `joker_transform` 变换，未变换 JOKER 在结算/揭示中的分值按 `_relic_card_value` 统一 +2（他人视角同值，非隐藏信息）。

`shop`：仅 `SHOP` 阶段存在，**按 viewer 投影**——`offers` 只含 viewer 自己的 2 个遗物位；`card_offers` 只含 viewer 自己的 3 个道具卡位（`target_mode` 公开，`locked` 为锁定状态）；`done` 为已结束商店的玩家 `SeatId` 名单；两个 `*_refresh_cost` 均为 10；`relic_bought`/`card_bought` 表示本店各自是否已购买。`shop_result`：每次购买**公开**广播，key 为 `"<kind>_<seat>_<slot>"`（kind=relic/card），随后开下一局；非 `SHOP` 阶段 `shop` 为空。`item_cards`/`item_card_used` 只下发给 viewer 本人，其他玩家不可见。

`pending` 是当前行动者待处理的抽牌，`CardView` 之上附带 `source: "draw" | "discard"`，用于客户端区分"可弃掉/可用能力"（仅抽牌堆）与"只可替换"（弃牌堆）。`source` 为公开信息，不泄露牌面。`pending.granted_ability`（`peek_own`/`peek_other`）仅在当前行动者抽到无能力奇数/偶数牌且触发「奇数/偶数视野」时出现，表示该牌获得一次性可选查看能力；只下发给当前行动者，不泄露牌面。

可见性规则：

1. `pending` 只发送给当前行动者，且仅在 `TURN_DECISION` / `Q_DECISION` 期间存在。
2. `slots[].card` 只在 `GAME_OVER` 时发送给所有玩家；其他时间一律只发送 `HiddenSlot`。
3. `discard` 始终是当前弃牌顶的公开 `CardView`；空弃牌堆发送 `{}`。`discard_count` 为弃牌堆张数；`discard_history` 为曾进入弃牌堆的牌（按时间顺序）——这些牌当时都通过弃牌顶公开过，属公开信息，供 stats 面板展示（不含任何隐藏牌面）。
4. `slots[].bomb` / `card.bomb` 只表示该槽位/卡牌带炸弹标记，不泄露牌面；`effect_pass` 不含 `picks`（不泄露已选牌）与任何牌面。
5. `slap_rank` 是弃牌顶的公开点数；`slap_open=true` 表示贴牌窗口开启（`TURN_DRAW` 期间，直到当前玩家抽牌）。客户端不得以本地计时决定窗口关闭。`settle_deadline_server_ms>0` 表示处于**结算贴牌窗口**（末位最终行动后，或手牌超限罚牌落地后）：不立即结算，`slap_open` 与 `TURN_DRAW` 保持、仅可贴牌，deadline 到时结算（贴牌判定结束后经收尾宽限提前结算）；客户端不得以本地计时决定结算时机。**倒计时一经开始不再重置**（窗口内后续贴牌/再次超限都不重制 deadline）。超限罚牌落地阶段 `slap_open=false` 且 `settle_deadline_server_ms=0`。
6. `slap_duel` 仅在 `SLAP_DUEL` 阶段存在：`contestants` 为比拼候选人、`duration_ms` 为扫动总时长、`deadline_server_ms` 为扫动截止（服务器时钟）、`target` 为加粗区中心（红心）位置，均为公开信息。客户端不得以本地计时决定比拼结果。
7. `event_log` 不得含有未公开的 `Rank`、`CardId` 或玩家私有查看结果。
8. 客户端收到小于等于本地 `state_revision` 的快照时必须丢弃；对局中止（`match_aborted`）后客户端重置 `last_seen_revision`，以接受新一局从 1 重新计数的快照。

### 4.2.1 身份注册回执 `registered` 与重连恢复 `resume_hand`

```text
// 注册成功后定向发给该玩家本人（不广播）
{
  player_token: String
}
```

`player_token`：服务器注册时生成的随机字符串，唯一标识玩家身份，客户端持久化到本地（`user://identity.cfg`）。断线重连凭它认领原座位。

```text
// 重连成功后定向发给该玩家本人（仅本人）
{
  hand: CardView[],       // 本人当前手牌面（空槽为 {}）
  pending: CardView | {}  // 当前待处理抽牌（若有且属于本人）
}
```

可见性规则：

1. `registered` / `resume_hand` 只发给对应玩家本人，绝不广播。
2. `resume_hand` 只含**本人自己的手牌面**与**自己的待处理牌**；曾偷看过的他人牌面不恢复（符合"记住看过什么"的记忆机制）。

```text
{
  protocol_version: 1,
  match_id: String,
  reveal_id: String,
  title_key: "INITIAL_PEEK" | "PEEK_OWN" | "PEEK_OTHER" | "Q_PEEK",
```

### 4.5 对局中止 `match_aborted`

```text
{
  protocol_version: 1,
  match_id: String,
  code: "MATCH_ABORTED_PLAYER_LEFT" | "HOST_DISCONNECTED",
  message_key: String
}
```

中止不是结算：不发送 `MatchResult`，不扣生命，不写入历史。客户端应清除对局本地状态并返回大厅/起始页面。

> **断线策略（已实现）**：非当前行动者掉线**不再中止对局**，而是标记 `offline`、加入 `offline_players`；只有当前行动者（或开局记忆阶段任一玩家）离线时 `suspended=true` 暂停。玩家凭注册时获得的 `player_token` 调用 `request_reconnect` 认领原座位：服务器更新其 peer_id、置回在线、定向补发本人手牌面 + 待处理牌并广播最新快照。房主可调用 `request_kick_offline(seat)` 踢出离线者并继续（踢出后剩余人数 < MIN_PLAYERS 时自动中止回大厅）、`request_abort_match` 中止回大厅（销毁房间），或 `request_close_room` 解散房间（广播 `match_aborted` + 关闭服务器连接，全员回初始大厅可重新建房/加入）。

### 4.6 查看高亮 `peek_highlight`

当某玩家执行看牌能力（7/8 看自己、9/10 看别人、Q 查看后决定）时，服务器向**除查看者外**的所有玩家广播被查看牌的位置。**3D** 下其他玩家据此把该牌**翻到「黑底闭眼」占位面** + 蓝光（比单纯蓝光更明显），到时翻回。

```text
{
  player_id: PeerId,
  slot: Slot,
  hold?: Boolean   // Q 的两张看牌：true → 其他玩家的闭眼占位翻转保持到本次 Q 决策结束、不自动翻回（由客户端在离开 Q_DECISION 时释放）
}
```

可见性规则：

1. 该消息**只包含位置**（`player_id` + `slot`，及可选的 `hold` 标记），**绝不包含 `CardId`、`Rank` 或任何牌面字段**；客户端只用于视觉标记，不写入公共状态。
2. 牌面仍通过 `private_reveal`（4.3）只发送给查看者本人；其他玩家仅看到"有人在查看某张牌"的位置提示，无法得知牌面（3D 显「黑底闭眼」占位面）。
3. 查看者本人不接收 `peek_highlight`（已通过 `private_reveal` 获得完整信息）。

### 4.7 动画事件 `card_exchange_animated`

服务器在状态广播**之前**向所有玩家广播动画事件（客户端先用旧布局定位），`kind` 决定客户端播放的动画：

```text
{
  kind: "replace" | "swap" | "discard" | "slap_penalty" | "slap_resolved" | "slap_gift" | "effect_pass" | "bomb_explode" | "effect_trigger" | "plus_one",
  ...字段见下表
}
```

| `kind` | 字段 | 隐私 |
| --- | --- | --- |
| `replace` | `actor, slot, old_data, big_data` | 旧牌/抽到的牌已是公共信息 |
| `swap` | `a, a_slot, b, b_slot, a_data, b_data` | J/Q 交换的牌面公开 |
| `discard` | `actor, big_data` | 弃掉的牌公开 |
| `slap_penalty` | `peer, slot` | **不含牌面**；罚牌对他人按背面动画，落地后由快照决定显隐 |
| `slap_resolved` | `actor, target, target_slot, card` | 被贴的牌已通过贴牌 reveal 公开；`actor` = 贴中者 seat（3D「贴牌成功」爆炸弹层据此显示名字） |
| `slap_gift` | `actor, own_slot, target, target_slot` | **不含牌面**（贴牌者自己的牌，他人只看背面） |
| `effect_pass` | `moves: [{from_seat, from_slot, to_seat, to_slot}]` | **不含牌面**；6 效果整桌传递，每段只看位置；仅打出者本人可看到自己已知的牌面，其余为背面 |
| `bomb_explode` | `seat, slots: Slot[], cards: CardView[]` | 炸弹已移出对局，**公开牌面**用于右侧爆炸 UI（`cards` 与 `slots` 对齐）；小爆炸按旧槽位位置播放 |
| `effect_trigger` | `actor, card: CardView, effect` | 6 效果触发：`card` 为打出的 6 / 红 Joker（均已公开），用于右侧成功 UI |
| `plus_one` | `seat, slot` | 左下角 +1 **真实生效后**由服务器广播（K/Joker/空槽不广播）；客户端据此飘 `+1` |

贴牌 reveal（`receive_reveal`，标题含"贴牌"）的 `target` 额外携带 `correct: Boolean`，客户端据此对被贴的牌打绿（对）/红（错）炫光；正确贴牌客户端 hold 翻牌至结算（`slap_resolved`），比拼败者由客户端翻回。

### 4.7.1 道具卡使用事件 `item_card_used`

服务器在道具卡使用时广播给所有客户端（**使用后卡面公开**；库存仍私有）：

```text
{ actor: SeatId, card: {id, name, desc, glyph, color, target_mode}, target: SeatId | -1 }
```

客户端复用贴牌成功爆炸弹层：标题=卡名、中间=道具卡正面、名字=使用者；爆炸层下方小字说明框显示卡牌说明 + 目标玩家名。

### 4.8 注视点 `look`（纯表现层）

`receive_look(seat: SeatId, target: Vector3, zoom: Boolean, talking: Boolean, nose: Vector3)` — 服务器把某玩家的**世界注视点（gaze target）**、放大/说话状态与**鼻子指针目标世界坐标**转发给**其他**客户端，用于让该席 3D 机器人跟随其"主人"（眼睛看向其注视点、放大时小眼、说话时嘴开合、鼻子指向目标点并随头摆动）。

- 上报：客户端在 3D 下按约 12Hz 调 `server_look(target, zoom, talking, nose)`（`target = 相机位置 + 相机前向 × 固定距离`；方向变化小于约 2.6°、zoom/talking 未变且 `nose` 未变则不发送）；服务器用 `_peer_to_seat(sender)` 校验后写入 `remote_looks`/`remote_zoom`/`remote_talk`/`remote_nose`（`nose` 非有限 → ZERO）并转发（房主本人走 `_apply_look`）。
- **不参与规则**：不判定、不锁阶段；`target` 必须有限，否则忽略。
- **不入快照**：不作为 `match_snapshot` 字段（避免污染对局状态与 `state_revision` 去重）；允许丢包。
- 客户端维护 `GameState.remote_looks`（注视点）/`remote_zoom`/`remote_talk`/`remote_nose`（均按 seat）；`Table3dView.update_avatars(cam, remote_looks, remote_zoom, local_zoom, remote_talk, local_talk)` 对每席优先用其同步值，缺省**稳定看向本机相机**并用本机 zoom/talk。接收端在 `RobotAvatar` 内做 Head Tracking + 相对头的 VRM LookAt（见 `3D角色与场景说明.md` §4.6/§4.7）。
- **鼻子指针**：`Table3dView.update_noses(remote_nose, local_target)` 把每席**目标世界坐标**下发到 `RobotAvatar.set_nose_target_world`（`Vector3.ZERO`=缩回）；鼻根随头、鼻尖定向到目标点，长度=鼻根→目标距离。方向无需额外同步（目标为共享世界坐标，各客户端确定性推出）。
- 向后兼容：`nose` 为可选参数（缺省 `Vector3.ZERO`），旧的 4 参 `server_look`/`receive_look`/`_apply_look` 调用仍有效。

### 4.9 桌面标记 `mark`（纯表现层）

`server_mark(pos: Vector3, style: String, icon: String, text: String)` → 服务器校验发送者（`_peer_to_seat`）后 `_apply_mark(seat,pos,style,icon,text)`：本地发 `mark_placed(seat,pos,style,icon,text)` 信号（房主可见）+ 转发 `receive_mark(...)` 给其他客户端；各客户端据此在桌面 `pos` 生成标记，3 秒自动消失。

- **触发**：3D 下**按住 D** 出四扇区轮盘（上眼/右问/下数/左叹，中心中空），拖到扇区松 D 放置；单点（中空/未选）不放置。落点 = 按住 D 时准星（屏幕中心）射线与桌面平面 `y=TABLE_HEIGHT` 的交点；仅当 `|x|,|z| ≤ TABLE_RADIUS` 才开轮盘/发送（桌外忽略）。
- **字段**：`style ∈ {ripple,nose}`（放置时按放置者设置 `gameplay.nose_click`：`false`→`ripple`、`true`→`nose`，随事件同步）；`icon ∈ {eye,question,number,exclaim}`；`text` 仅 `number` 用（= 当前弃牌堆顶 rank，空弃牌堆 → `"-1"`）。
- **事件式、无状态存储、不入快照**：`pos` 须有限否则忽略；不判定、不锁阶段。
- 见 `3D角色与场景说明.md` §4.10。

### 4.10 表情 `emote`（纯表现层）

`server_emote(index: Int)` → 服务器校验发送者（`_peer_to_seat`）后 `_apply_emote(seat,index)`：本地发 `emote_played(seat,index)` 信号 + 转发 `receive_emote(seat,index)` 给其他客户端；各客户端据此在该席角色头顶显示表情（占位=数字 billboard，2.5s 消失）。

- **触发**：3D 下**按住 Y** 出 6 扇区轮盘（数字 1–6，中心中空），拖到扇区松 Y 播放；单点（中空/未选）不播放。
- **字段**：`index` 0–5（表情编号，占位=显示 `index+1`）；将来映射到 avatar 真实动作，协议不变。
- **事件式、无状态存储、不入快照**：不判定、不锁阶段；自己角色隐藏 → 自己看不到自己的表情。
- 见 `3D角色与场景说明.md` §4.11。

### 4.11 重开本局 `restart_match` + 开局发牌动画

- `request_restart_match(action_id)`（房主）→ 服务器 `_server_restart_match` 校验（非 LOBBY、seat0、人数 ≥ MIN）→ `_deal_new_match()`：新 `match_id`、重发手牌、回 `INITIAL_PEEK`；保留 `match_number`/货币/生命/系列赛/`run_state`。
- **开局发牌动画**（纯客户端，无协议）：客户端检测快照 `match_id` 变化 → `Table3dView.play_deal()` 从抽牌堆逐张飞到各席（3D，卡背）。**按住空格 2 倍速**。
- 见 `3D角色与场景说明.md` §4.12。

## 5. 幂等、顺序与贴牌

1. 客户端每次点击产生唯一 `client_action_id`；同一个 ID 重传时，服务器只能返回首次结果或同一拒绝，绝不能再执行一次。
2. 服务器对每个玩家保留最近 64 个动作 ID，离开房间后清除。
3. 服务器每次接受动作后递增 `state_revision`；所有更改后的快照都带新 revision。
4. 贴牌窗口无固定时长：上一玩家弃牌/用技能后开启（`slap_open=true`）并推进回合；**下一玩家 `take` 时窗口关闭**。正确贴牌进入判定（见第 6 条）；窗口关闭后到达的贴牌请求收到 `DUPLICATE_OR_EXPIRED_ACTION`，不受罚。
5. 同一窗口内玩家可多次尝试；错误贴牌每次罚抽并继续窗口。客户端在判定翻牌期间应忽略新的贴牌点击。
6. 比拼判定：首个正确贴牌开启 **400ms 收集窗**，期间其他正确贴牌加入；结束后仅 1 人则正常解决并关闭窗口，≥2 人进入 `SLAP_DUEL`，各候选人按 `slap_duel_stop`，服务器按**到达时间**映射为扫动位置，最接近 `target`（红心）者获胜并正常解决贴牌，败者无惩罚。未按 STOP 者视为最差距离。
7. 客户端不设贴牌倒计时；窗口关闭由服务器 `slap_open` 状态决定。

## 6. 安全、日志与敏感信息

- LAN MVP 假设玩家彼此可信；它不提供身份认证或端到端加密。
- 服务器权威、私有快照和不透明 `CardId` 用于防止正常客户端“顺手看到”暗牌，不承诺防御能修改自己客户端的恶意玩家或恶意房主。
- 服务器事件日志必须只记录：`match_id`、`state_revision`、请求类型、调用 peer、接受/拒绝码、阶段、耗时。不得在结算前记录真实暗牌。
- 调试日志如确需记录牌面，必须只在本地开发构建启用，并明确不上传、不进入公开崩溃报告。

## 7. V1 对齐验收

协议视为完成前，至少满足：

- [ ] 客户端版本不符无法加入大厅。
- [ ] 所有普通快照都能按 `state_revision` 丢弃旧包。
- [ ] T20 的暗牌泄露检查通过。
- [ ] 每个请求都有对应的接受路径与至少一个拒绝码测试。
- [ ] 连续双击/重传同一动作不会造成双抽、双换或双贴。

## 8. 目录服务协议（P2，独立于游戏 ENet 协议）

> 中心房间目录服务：把"输 IP:端口"变成"建房拿码、输码加入"。**方案 A：独立 HTTP/JSON 服务**（`server/directory/directory.py`），与游戏 ENet 协议相互独立。**房间地址 = 请求方公网源 IP** + 上报端口（宿主无需自探测 IP）。

| 请求 | 载荷 | 响应 | 说明 |
| --- | --- | --- | --- |
| `POST /create_room` | `{port, mode, max_players}` | `{code, expires_in}` | 分配 6 位随机短码；`host` 取源 IP |
| `POST /join_room` | `{code}` | `{host, port, mode}` \| `{error:"ROOM_NOT_FOUND"}` | 查码得地址 |
| `POST /heartbeat` | `{code}` | `{ok}` | 宿主续命（默认 10s 一次） |
| `POST /close_room` | `{code}` | `{ok}` | 主动回收 |
| `GET /health` | — | `{ok, rooms}` | 健康检查 |

- **短码**：6 位 Crockford base32（去 I/L/O/U）；**码 TTL 30min（仅限制"用码加入"）**；心跳超时 30s 回收；按源 IP 限速（防枚举）。
- **与断线重连无关**：重连用 `player_token`（游戏协议），与短码无关。
- **不入游戏快照**：目录只做"码↔地址"，不接触牌局数据。
- 客户端 `DirectoryClient`（`scripts/net/directory_client.gd`）负责调用；地址配置项 `Settings.network.directory_url`。
- 部署：VPS 上另起该服务（TCP 8080，见 `server/directory/README.md`）。

## 9. 账号服务协议（P3a，独立于游戏 ENet 协议）

> 持久账号（跨会话/跨房间）：设备匿名注册、昵称、持久战绩。**方案 A：独立 HTTP/JSON 服务**（`server/account/account.py`，TCP 8090）。**与 Steam 无关**（P3b/P3c 待 Steam 资源）。

| 请求 | 载荷 | 响应 | 说明 |
| --- | --- | --- | --- |
| `POST /register_device` | `{name?}` | `{account_id, secret}` | 分配 `acc_`+16hex、32hex secret；数据落盘 |
| `POST /login` | `{account_id, secret}` | `{account_id, name, stats}` \| `{error:"AUTH_FAILED"}` | 校验 |
| `POST /set_name` | `{account_id, secret, name}` | `{ok}` | 改昵称（≤16 字） |
| `POST /get_profile` | `{account_id}` | `{account_id, name, stats}` | 资料 |
| `GET /health` | — | `{ok, accounts}` | 健康 |

- `stats` 现含 `{wins, matches}`（为 P4 ranked 铺路）。
- 客户端 `AccountClient`（`scripts/net/account_client.gd`）+ 本地身份 `user://account.cfg`；配置项 `Settings.network.account_url`。
- **连接握手**：`request_register_player` 增可选 `account_id`（第 3 参，缺省=匿名/兼容旧客户端）；服务器存 `players[].account_id`（**内部用、默认不下发快照**）。
- 部署：VPS 上另起该服务（TCP 8090，见 `server/account/README.md`）。

## 10. Steam 认证（P3b，桩先行）

> 用 Steam 身份绑定账号。**桩先行**：服务端 `MockVerifier`（`ticket="mock:<steamid>"` 通过）顶替真校验；客户端 `SteamBridge` 在无 GodotSteam 时走桩。真机联调待 Steamworks 资源（App ID/Web API Key + GodotSteam）。

- 账号服务端点 `POST /steam_auth {account_id, secret, ticket}` → 服务端校验（`SteamWebApiVerifier` 调 `ISteamUserAuth/AuthenticateUserTicket/v1/`，或 `MockVerifier`）→ 绑定 `account.steam_id` → `{ok, steam_id, owner}`；错误 `AUTH_FAILED` / `STEAM_AUTH_FAILED`。
- 服务端选型：`--steam-webapi-key` 有则真校验，否则 Mock（并打印模式）。
- `steam_id` **不下发游戏快照**（仅账号服务侧）。
- 客户端：`SteamBridge`（`available()` 检测 GodotSteam）+ `AccountClient.steam_auth`；无插件→桩（不崩）。好友/邀请同经 `SteamBridge`（桩下提示"Steam 未启用"）。
- 部署：Web API Key 存**环境变量/参数**，不入库/不入仓。
