# 3D 角色与场景说明（模型嵌入 · 3D 布局 · 路线图）

> **本文档职责**：专门讲 KONG 的 **3D 对局视图**——场景如何搭建、文件在哪、坐标/朝向与尺度约定、**角色（Robot）系统**如何接入、以及"3D 角色"三阶段路线图（① Robot 头像 → ② 眼部追踪 → ③ 手部动作）。
> **给谁看**：AI Agent（改 3D 前必读）+ 开发者（调参/建模参考）。
> **权威边界**：规则/协议/快照/状态机以 `KONG_开发文档.md`、`网络协议_V1.md` 为准；本文件只讲**纯客户端展示层**。工程现状与全局不变量见 `AI_AGENT_交接说明.md`。

---

## 1. 范围与不变量

- 3D 对局视图是**纯客户端展示层**：只读公开快照渲染、只发 `request_*` 意图；**不改**规则/协议/快照/状态机。
- 角色（RobotAvatar）**不挂碰撞层**，不参与准星拾取；拾取只属于卡牌/牌堆/铃铛/HUD（`Table3dLayout.PICK_LAYER`）。
- 对局进入 3D 的入口与生命周期在 `scripts/ui/main.gd`；`scenes/ui/table3d.tscn` **归开发者所有**，节点名/路径是契约（`Table3dView._bind()` 按固定路径解析，缺节点 `push_error` 不静默）。
- 玩家身份是 `seat_id`（0..N-1）；3D 座位按 `seat_angles` 与 2D 箱位对齐。

## 2. 3D 对局场景 setup

### 2.1 切换与入口

- 对局中按 `F10`（macOS 上 F 键为媒体键，**备用键 `V`**）在 2D 与 3D 间切换。逻辑在 `main._set_table3d(on)`。
- 进 3D：捕获鼠标（`MOUSE_MODE_CAPTURED`）、实例化 `scenes/ui/table3d.tscn`、`table3d.render(latest_state, interaction.card_actionable)`。
- 每帧（`main._process`）：`table3d.update_facing()`（大牌朝相机）→ `table3d.update_avatars(cam)`（机器人眼动）→ 准星悬停 `table3d.update_hover()`。
- 输出 3D：`_set_table3d(false)` → `clear_hover()` / `reset_zoom()` / `set_active(false)`，恢复 2D 与鼠标。
- 相机环视：`main._input` 里 `InputEventMouseMotion` → `table3d.camera.look(event.relative)`（走 `_input` 早于 GUI，避免被 Control 吞掉）。按住 `Command/Alt` 拉近视场（`Table3dCamera.set_zoom`）。
- 准星：`Crosshair`（`main` 子节点）用 `set_anchors_and_offsets_preset(PRESET_CENTER)` 居中于屏幕；`pick_center`/`update_hover` 始终以**视口中心**为准（与准星视觉一致）。
- 说话：3D 下按 **M** 切换说话（嘴开合）；`Tab` 手册；`Esc` 退出 3D（或先关手册/看板）。

### 2.3 坐标与朝向约定（关键）

- **座位取位（固定，共享世界）**：座位在半径 `SEAT_RADIUS=3.0` 的圆上，角度由 `Table3dLayout.seat_angle(seat_id)` **按 seat_id 固定**：seat0=0°、seat1=270°、seat2=90°、seat3=180°（**不再**按观看者重排）。所有客户端世界坐标一致，观看者总把自己的座位放到相机处（视觉上仍是"自己近侧"）。座位节点 `rotation_degrees.y = angle + 180`。
  > 早期实现按"viewer→0、其余按 id 排序取 `[270,90,180]`"分配角度，这会让同一座位在不同客户端处于不同角度（且非刚性旋转），导致同步的世界注视方向被镜像——现改为固定角度。`seat_angles(count)` 仅留给沙盒等纯展示按序取角度用。
- **座位本地轴**：座位**本地 +Z 指向桌心**（所以本地 +Z 是"朝向桌子"）。`HandAnchor`/`Avatar` 都在座位本地坐标下。
- **相机**：`frame_for_seat(angle, target_height)` 把 rig 放到 `dir*(SEAT_RADIUS+CAMERA_BACK) + Y*EYE_HEIGHT`，默认俯角 `aim_pitch_deg(EYE_HEIGHT - target_height, ...)` **对准桌面中心**（`render` 传 `TABLE_HEIGHT`，保证准星起始落在桌面）。相机视线水平方向 = 从相机指向桌心。
- **桌面高度**：`Table3dLayout.TABLE_HEIGHT = 1.0`（世界 Y）。机器人**脚仍在 y=0（地面）**，故桌子抬到**玩家腰间**（此前桌顶在 y=0 显得桌子在地上）。桌/边框/中央牌堆（`Center` 整节点）/手牌区（`HandAnchor`，`_bind` 设 `TABLE_HEIGHT+0.03`）都抬到该高度；看板沿"相机→桌面中心"连线放置（`main._place_boards`）。
- **viewer 自身**：自己那席的 `Avatar` 整株隐藏（第一人称），只看到别人的角色。
- **尺度**：见 §4.3。

### 2.4 渲染流程（`Table3dView`）

`render(state, actionable)` 全量重建（无增量）：
1. 取 `viewer_id` / `players`，算每席角度 → 相机 `frame_for_seat`。
2. 逐席：`node.visible/position/rotation` → `_render_seat`（填每槽 `CardBlock`）→ `_apply_avatar`（角色定位/overlay/面板/回合标识）。
3. 重放跨 render 状态：`_reveals`（揭示/翻牌）、`_flashes`（peek 蓝光）、`_hover_slot`（悬停抬起）。
4. 中央：抽牌堆光晕、弃牌顶、大牌竖立、铃铛可用性、HUD 位置。

## 4. 角色（Robot）系统

### 4.1 接入方式（代码包装）

- 在 `Table3dView._bind()` 为每席 `Avatar` 调用 `_attach_robot(avatar)`：
  - `RobotAvatar.new()` 挂到 `Avatar` 下，命名 `RobotAvatar`；
  - 隐藏旧占位 `Avatar/Head`、`Avatar/Body`（**节点保留**，保持 tuner/测试与路径契约）。
- `_apply_avatar()` 每帧（每次 render）：
  - `avatar.visible = seat != viewer`（自身隐藏）；
  - `robot.position.y = -eye`（脚落在桌面，见 4.3）；
  - `robot.set_overlay(overlay)`（仅出局/离线=变暗；**不再按回合染色**，其余=清除）；
  - 头顶 `StatPanel` 与 `TurnMarker` Y 随机器人高度定位。
- 每帧 `Table3dView.update_avatars(cam, GameState.remote_looks)`：每席**优先**用其**主人同步来的注视方向**（`robot.set_eye_direction(dir)`，见 §4.5），无同步数据时**稳定看向本机相机**。

### 4.2 `RobotAvatar` 职责与常量（`scripts/ui/robot_avatar.gd`）

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `ROBOT_SCENE` | `res://assets/characters/source/Robot.blend` | 模型（PackedScene） |
| `STRIP_NODES` | `["Camera","Light"]` | 实例化后剔除的自带相机/灯（防成为当前相机/多打一盏灯） |
| `MODEL_EYE` | `(0, 2.038, 0.215)` | 眼球中心（模型空间；+Z=脸朝向） |
| `MODEL_HEAD_TOP` | `2.2` | 头顶高度（模型空间） |
| `SCALE` | `1.65` | 整体缩放（原 1.1 × 1.5）；**越大越高越可能出画**（脚在原点、相机俯角较大，见 4.3） |
| `ARM_DOWN_DEG` | `82` | 上臂由 T-pose 放下角度 |
| `EYE_YAW_MAX_DEG` / `EYE_PITCH_MAX_DEG` | `32` / `18` | 眼动满权重对应偏航/俯仰角 |
| `EYE_GAIN` | `1.0` | 眼动强度 |
| `HEAD_YAW_MAX_DEG` / `HEAD_PITCH_MAX_DEG` | `30` / `20` | Head Tracking 上限：头先吸收到该角度，眼睛只做剩余 |
| `BLINK_PERIOD` / `BLINK_DURATION` | `4.2` / `0.14` | 自动眨眼周期/时长 |
| `BODY_COLOR` / `BODY_METALLIC` / `BODY_ROUGHNESS` / `BODY_SPECULAR` | `#496AFE`（默认） / `0.7` / `0.35` / `0.5` | 机体金属材质参数；实际颜色由每玩家分配（`set_body_color`） |
| `KongRules.PLAYER_COLORS` | 8 色 | 玩家配色池：`#3ABA64 #BD414B #A36DE9 #7158FE #A0D45D #B18C3E #63CBEA #496AFE` |

要点：
- **待机姿势**：模型 rest 是 **T-pose**（双臂平伸）。`_apply_idle_pose()` 用 `Skeleton3D.set_bone_global_pose_override(bone, target, 1.0, true)` 把 `upper_arrm.L`/`upper_arm.R` 绕世界 Z 轴放下 82°（左 -、右 +），子骨骼（小臂/手）随之联动。注意骨骼名**拼写**：`upper_arrm.L`（双 r）、`upper_leg_R`（下划线 R）。
- **overlay**：`set_overlay(mat)` 递归给模型所有 `MeshInstance3D` 设 `material_overlay`（传 `null` 清除）。与 2D/3D 既有染色策略一致，不改材质本体。
- **眼动（VRM LookAt，head-relative，见 §4.6）**：`set_gaze_target_world(target)`（世界注视点）/ `set_eye_direction(dir_world)`（世界方向，同步用）→ 转到 **Head 参照**的 LookAt space → `RobotAvatarMath.eye_look_weights()` → `Eyes.set_blend_shape_value()`；`reset_eyes()` 归零；`_process` 里按周期自动眨眼。
- **机体颜色（每玩家随机）**：进入游戏时服务器从 `KongRules.PLAYER_COLORS`（8 色）随机取**未占用**色写入 `players[seat].color`（保证不重复），随快照下发；`table3d_view._apply_avatar` → `robot.set_body_color(color)`。`RobotAvatar` 用**逐实例 `set_surface_override_material`**（Arms/Body/Legs 单面 + Face 面 0）上色，**不改共享网格/材质**，故各玩家可不同色；无分配色时用默认 `BODY_COLOR`。断线重连保留原色（按 seat）。
- **放大联动（小眼睛）**：`Table3dCamera.zoomed`（按住 Command/Alt）+ 随注视同步（`GameState.remote_zoom`）→ `Table3dView.update_avatars(cam, remote_looks, remote_zoom, local_zoom, remote_talk, local_talk)` → `RobotAvatar.set_eye_zoom(on)`：把 `Tiny_Eyes` 形状键设为 1（小眼睛），松开归零。注意这是**小眼形状**而非换材质（换 Eye2 材质会把眼睛变白、像"消失"）。每席用其**主人**的 zoom；无同步用本机 zoom。
- **说话（M 键）**：`set_talking(on)` 驱动下巴 `jawOpen`；`RobotAvatarMath.talk_jaw(t)` = 多正弦叠加（~4–10Hz）+ 慢包络，模拟开合嘴（无音素输入时的通用做法）。嘴在**下巴网格**（Face 等），故对所有含 `jawOpen` 形状的网格设置（`_jaw_targets`）。M 键切换（`main._input` 3D 分支），状态随注视同步（`GameState.remote_talk`，`server_look`/`receive_look` 带 `talking`）。自己角色第一人称隐藏 → 需在别的窗口看自己说话。

### 4.3 放置数学（为什么是这些值）

- `Avatar` 原点在**眼高**：`avatar.position = (0, EYE_HEIGHT, -CAMERA_BACK)`（座位本地），即世界 y≈3.5、径向外移 1.5（座位半径 2.4 → 角色在半径 3.9，恰在桌边 3.8 外侧）。
- 机器人模型**原点在脚**（脚 y≈0），故 `robot.position.y = -EYE_HEIGHT` 使脚落在桌面 y=0。
- 头顶世界高度 = `MODEL_HEAD_TOP * SCALE`（脚在 0）。`StatPanel`/`TurnMarker` 用同式定位（`head_top_local = MODEL_HEAD_TOP*SCALE - eye`）。
- **可见性约束**：相机俯角 `atan2(EYE_HEIGHT, SEAT_RADIUS+CAMERA_BACK)=atan2(3.5, 4.5)≈37.9°`，竖直半 FOV≈37.5° → 视野上缘只在水平线下约 0.4°。对桌对面（水平距离≈7.5）可见的**头顶上限约 y≈3.45 → SCALE≤~1.57**。
- 当前 **SCALE=1.65**（头顶≈3.63）：对桌对面的**头顶会略微出画**（眼睛 y≈3.36 仍在画面内），且 `StatPanel`/`TurnMarker`（随 `MODEL_HEAD_TOP*SCALE` 上移）可能贴近/超出上缘。若要整体放大又不出画：同步抬高 `CameraRig.EYE_HEIGHT`（如 3.5→~4.3）或减小 `CAMERA_BACK`，或把 `SCALE` 调到 ≤1.57。

### 4.4 朝向

- 机器人本地 **+Z = 脸朝向**；座位本地 **+Z 指向桌心**；故 `RobotAvatar` 无额外旋转即**面朝桌心**（对面座位的机器人正对 viewer）。

### 4.5 注视同步（每人跟踪自己的鼠标）

**问题**：每台客户端只知道自己（本机）的鼠标/相机；若不联网，"别人那席的机器人"无法知道别人在看哪。（曾错误地退化为"所有机器人看向本机瞄准点"——瞄准点会因命中分支切换落到侧位机器人反侧，导致眼球瞬间翻转；现改为无同步时稳定看向本机相机。）

**方案**（轻量 RPC，纯表现层，不入快照，详见 `网络协议_V1.md` §4.8）：
- 客户端 3D 下每帧算本机**世界注视点** `target = cam.global_position + (-cam.global_transform.basis.z) * LOOK_TARGET_DISTANCE`，按 ~12Hz（`LOOK_SEND_INTERVAL`）且方向变化 >`LOOK_SEND_EPS_DOT`（≈2.6°）才上报。
- 房主：`GameState._apply_look(seat, target)`；客户端：`GameState.server_look.rpc_id(1, target, zoom)`。
- 服务器校验发送者后写入 `remote_looks[seat]` 并转发 `receive_look` 给其他客户端。
- 每席渲染：`update_avatars` 用 `remote_looks[seat]` → `robot.set_gaze_target_world(target)`（空渲染于 Head 参照，§4.6）；没有该席数据时 → `robot.set_gaze_target_world(cam.global_position)`（稳定看向本机，**不随本机瞄准点抖动**）。

**结果**：A 的屏幕里，B 的机器人看向 **B 自己**鼠标/相机指的方向；双开时两个窗口各自独立，互不干扰。因座位角度**固定（共享世界，§2.3）**，该世界方向在所有客户端一致 → A 看向 B 时，B 会看到 A 的机器人看着自己（眼神接触），不会镜像。

### 4.6 VRM 1.0 LookAt（head-relative）

> **重要**：本模型**不是 VRM**（无 VRM 插件/无 `VRMC_vrm` 扩展/无 `leftEye`/`rightEye` 骨骼），眼睛由 **ARKit 形状键**驱动 = VRM lookAt 的 **`type:"expression"`** 路径。因此无法"复用 VRM 插件 LookAt"，而是实现其**算法语义**。

参照 `VRMC_vrm.lookAt`：
- **LookAt space 基于 Head**（不是机器人根！）：`RobotAvatar._lookat_basis_model() = Head当前姿势 × Head rest 旋转的逆`。头未转动时为单位阵（+Z=模型前向）；头转动时随之旋转 → 眼睛**相对头补偿**，**不会重复叠加头的旋转**（Head Tracking 与 Eye LookAt 相互独立）。
- **origin ≈ `offsetFromHeadBone`**：用两眼中心 `MODEL_EYE`，并随 Head 姿势移动（`_eye_origin_model()`）。
- **RangeMap**：`inputMax` = `EYE_YAW_MAX_DEG`(32) / `EYE_PITCH_MAX_DEG`(18)，`outputScale` = 1；按 VRM `expression` 语义做 `min(|deg|, inputMax)/inputMax`，映射到 `eyeLookIn/Out/Up/Down ± Left/Right`。
- **API**：`set_gaze_target_world(target_world)`（世界注视点 → 先 Head Tracking 转头、再眼残余 LookAt）；`set_eye_direction(dir_world)` / `set_eye_look(target)` 为**仅眼**低层 API（不动头）。输入始终是**世界方向/注视点**，不是 Mouse X/Y → 便于日后接 webcam/手柄。

### 4.7 Head Tracking（头跟随注视点）

VRM `lookAt` **只管眼睛**；让头转是独立系统 **Head Tracking**（`Input → Head Rotation → Head Bone`）。本实现把它并入 `set_gaze_target_world`：
- 注视点 → 模型空间方向 → `yaw=atan2(x,z)`、`pitch=atan2(y, horiz)`；
- 分别 clamp 到 `HEAD_YAW_MAX_DEG`(30) / `HEAD_PITCH_MAX_DEG`(20)，以**全局姿势 override** 旋转 `Head` 骨骼（yaw 绕模型 +Y、pitch 绕模型右轴 -X；绕头骨原点，轴为模型轴）；
- 眼睛再做**相对头**的残余（§4.6）→ 头/眼不叠加：20° 目标头全吸收、眼≈0；45° 目标头到 30°、眼做 15°。
- **无需额外同步**：世界/座位已统一，头姿势可由同一 gaze target 在各客户端**确定性推出**。
- 关闭/无目标时 `reset_eyes()` 一并把头回正。

（未做：face/webcam 追踪、平滑、弹簧、收敛、UI —— 按需再加。）

### 4.8 说话动画（M 键，嘴开合）

- 形状键：`jawOpen`（模型自带，位于**下巴网格** Face 等；不在 Eyes）。`RobotAvatar._build` 收集所有含该形状的网格到 `_jaw_targets`。
- 驱动：`set_talking(on)` + `_process` → `RobotAvatarMath.talk_jaw(t)`（多正弦叠加 `0.55·6Hz + 0.30·9.7Hz + 0.15·4.1Hz` × 慢包络 `0.6~1.0`，clamp 0..1）→ 模拟开合嘴（**无音素输入时的通用做法**；进阶可用 viseme/能量驱动）。
- 输入与同步：3D 下按 **M** 切换（`main._input` 的 `KEY_M`，本地 `_talking_local`）；随注视同步（`server_look(target, zoom, talking)` / `receive_look(seat, target, zoom, talking)` → `GameState.remote_talk`）→ `update_avatars(..., remote_talk, local_talk)` → 逐席 `set_talking`。
- 注意：自己角色第一人称隐藏，说话要在**别的窗口**看自己；无同步时用本机 talking。

`hips, spine, chest, neck, Head, Mouth, shoulder.L, upper_arrm.L, lower_arm.L, hand.L, shoulder.R, upper_arm.R, lower_arm.R, hand.R, upper_leg.L, lower_leg.L, foot.L, upper_leg_R, lower_leg.R, foot.R`

> 手臂链：`shoulder.*` → `upper_arm*` → `lower_arm.*` → `hand.*`。Phase 3 手部动作主要动 `upper_arm*/lower_arm.*/hand.*`。

### 5.3 Blendshape（15，ARKit 子集，索引 0..14）

`eyeLookDownLeft, eyeLookDownRight, eyeLookUpLeft, eyeLookUpRight, eyeLookOutRight, eyeLookOutLeft, eyeLookInRight, eyeLookInLeft, eyeBlinkLeft, eyeBlinkRight, eyeWideLeft, eyeWideRight, Cute_Eyes, Tiny_Eyes, jawOpen`

- 眼动只用到前 8 个（Look*）+ 2 个 Blink*；`jawOpen`/`Cute_Eyes`/`Tiny_Eyes` 预留（嘴部/表情）。
- 每个网格都带 15 个同名形状键，实际有效值集中在 `Eyes`/`Face`；`RobotAvatar` 只操作 `Eyes`。
- 形状键是**每实例**覆盖（共享 mesh 资源不影响彼此）→ 4 个座位眼动各自独立。

### 5.4 眼动映射（`robot_avatar_math.gd`）

- 本地轴：`+X=左, -X=右, +Y=上, +Z=前`。
- `h = atan2(dir.x, dir.z)/yaw_max`（>0 看左），`v = atan2(dir.y, horizontal)/pitch_max`（>0 看上），夹取 [-1,1]。
- 看左：`eyeLookOutLeft=h` + `eyeLookInRight=h`；看右：`eyeLookInLeft=-h` + `eyeLookOutRight=-h`；看上/下：`eyeLookUp*/Down*` 双眼同值。
- 触发：`Table3dView.update_avatars(...)` 每帧——某席**优先**用其同步来的注视方向（§4.5），无同步数据时**稳定看向本机相机**（相机位置固定，不随环视抖动，避免眼球翻转）。映射前先转到 **Head 参照**（§4.6），头转动不叠加。
