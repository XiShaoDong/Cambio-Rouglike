## 2. 玩家可见规则

- 获得方式与选择时机：局间商店竞拍获得。
- 可见文本："下一局随机保护你一个格子，该格免疫其他玩家的贴牌与交换。"
- 触发时机：购买后在**下一局开局**随机选一格生效（护盾◈ 标记展示）。
- 次数、冷却或消耗：一次性；生效一局后失效（局开始即消耗）。
- 玩家需要做出的选择：无（随机选格）。
- 是否公开给其他玩家：是——护盾格带 `protected` 标记（所有玩家可见，避免误点）。

## 3. 服务器规则规格

| 项目 | 规定 |
| --- | --- |
| 事件钩子 | `on_match_start` → `_apply_match_start_relics`（随机选格 + 消耗遗物） |
| 前置条件 | 持有 `relic_guard_shield`；存活（参与下一局） |
| 输入上下文 | `run_state.relics`；不读取暗牌 |
| 状态改变 | `players[seat].protected_slot = randi() % HAND_SIZE`；从 `run_state.relics` 移除护盾（消耗）；快照槽位 `protected` 标记 |
| 随机性与随机源 | 服务器 `randi()`（无种子要求） |
| 结束条件 | 一局结束后护盾格随新局重置（-1） |
| 非法/重复请求行为 | 他人贴护盾格 → `PROTECTED`；他人 J·Q 交换指定护盾格 → `PROTECTED` |
| Feature flag | `run_state.relics` 为空即完全关闭（基础模式零影响） |

## 4. 信息可见性与反制

| 问题 | 答案 |
| --- | --- |
| 持有者得到什么信息？ | 知道哪格被保护（标记可见）。 |
| 其他玩家得到什么信息？ | 知道护盾格（标记可见），从而避开或调整策略。 |
| 是否会永久记录暗牌？ | 否。 |
| 对手有哪些可理解的反制或风险？ | 换去攻击其他三格；护盾不防看牌（对手仍可 peek 护盾格），信息侧不受保护。 |
| 是否影响贴牌服务器先后顺序？ | 否（仅拒绝指定护盾格，不改变裁决时序）。 |

## 5. 平衡假设

- 希望增强的核心决策：防御性换牌/手牌管理（保护关键记忆格）。
- 预期选择率区间：中。
- 可接受的持有者胜率变化：+0~3%。
- 最坏滥用方式：反复购买护盾保护同一记忆格 → 单局一次性、每局随机格，且护盾不防看牌，难以稳定压分。
- 明确禁止的组合：无。
- 下调、停用或移除的触发阈值：若选择率 >80% 且胜率 >+5%，改为随机两格二选一或提高价格。

## 6. 验收用例

| ID | 场景 | 预期 |
| --- | --- | --- |
| RLC-01 | 购买护盾后下一局开局 | 随机保护一格（`protected_slot` ∈ 手牌槽）、遗物被消耗 |
| RLC-02 | 他人贴护盾格 / J·Q 交换指定护盾格 | 拒绝（`PROTECTED`）；其他格正常 |
| RLC-03 | 护盾格被看牌 | 正常（护盾不防看牌） |
| RLC-04 | 私有信息检查 | 护盾格标记公开，不泄漏任何牌面 |
| RLC-05 | 基础模式共存 | 无护盾时 `protected_slot == -1`，无 `PROTECTED` 拒绝 |
| RLC-06 | 反例 / 对手交互 | 护盾格被本人替换/弃牌后，新卡仍受保护（槽位保护不随卡移动） |
