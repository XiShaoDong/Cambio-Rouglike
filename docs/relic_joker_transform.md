## 2. 玩家可见规则

- 获得方式与选择时机：局间商店竞拍获得（价高者得）。
- 可见文本："抽到 Joker 时可变换为任意一张牌；未变换的 Joker 计 2 分。"
- 触发时机：持有者在自己抽牌阶段抽到 Joker（抽牌堆或弃牌堆顶）后、处理该牌前，可主动选择变换。
- 次数、冷却或消耗：每抽到一张 Joker 即可触发一次（无全局次数限制）。
- 玩家需要做出的选择：选点数（A~K）+ 花色（♠♥♣♦）变换；或不变换直接按 Joker 处理。
- 是否公开给其他玩家：持有遗物本身公开（`run.relics` 入快照）；抽到 Joker 与否/是否变换由行动者待处理牌可见性决定（他人只见背面 pending）。

## 3. 服务器规则规格

| 项目 | 规定 |
| --- | --- |
| 事件钩子 | `on_draw_joker`（TURN_DECISION 且 pending 为 JOKER）→ `_server_joker_transform`；`before_score` → `_relic_card_value`（未变换 JOKER +2） |
| 前置条件 | 当前行动者；持有 `relic_joker_transform`；`pending_draw` 牌面 rank 为 `JOKER`；`rank`/`suit` 合法 |
| 输入上下文 | 只读取 `pending_draw.card_id` 与 `run_state.relics`；不读取其他玩家暗牌 |
| 状态改变 | 把 pending 卡 `cards[cid].rank/suit/value` 改为所选牌；广播状态（他人仍只见背面 pending） |
| 随机性与随机源 | 无 |
| 结束条件 | 变换后按普通抽牌流程处理（替换/弃牌/能力） |
| 非法/重复请求行为 | 非 JOKER / 无遗物 → `ABILITY_FORBIDDEN`；非当前行动者 → `NOT_CURRENT_PLAYER`；重复 action_id → `DUPLICATE_OR_EXPIRED_ACTION` |
| Feature flag | `run_state.relics` 为空即完全关闭（基础模式零影响） |

## 4. 信息可见性与反制

| 问题 | 答案 |
| --- | --- |
| 持有者得到什么信息？ | 自己抽到 Joker 并可选变换（pending 本人可见）。 |
| 其他玩家得到什么信息？ | 只知某人持有该遗物；pending 大牌仍为背面。 |
| 是否会永久记录暗牌？ | 否。 |
| 对手有哪些可理解的反制或风险？ | 未变换的 Joker 计 2 分（0→2）是持有者的"负收益"代价；对手可据此推断其手中 Joker 偏贵。 |
| 是否影响贴牌服务器先后顺序？ | 否。 |

## 5. 平衡假设

- 希望增强的核心决策：抽牌/换牌路线的信息与风险取舍。
- 预期选择率区间：中（有代价，非必选）。
- 可接受的持有者胜率变化：+0~3%。
- 最坏滥用方式：把 Joker 变换成低分 A/K 压总分 → 用 +2 代价对冲，不破坏结算。
- 明确禁止的组合：无（+2 已含在代价内）。
- 下调、停用或移除的触发阈值：若选择率 >80% 且胜率 >+5%，上调未变换 Joker 分值或限制每局次数。

## 6. 验收用例

| ID | 场景 | 预期 |
| --- | --- | --- |
| RLC-01 | 持有者抽到 Joker 后调 `joker_transform` | pending 卡 rank/suit/value 变为所选；他人快照仍为背面 pending |
| RLC-02 | 无遗物者 / 已变换后再次变换 | 拒绝（`ABILITY_FORBIDDEN`） |
| RLC-03 | 未变换 JOKER 结算 | 持有者计分 = 2（他人同值），排名一致 |
| RLC-04 | 私有信息检查 | 快照不含他人暗牌牌面；仅 pending 行动者本人可见 |
| RLC-05 | 基础模式共存 | 无遗物时 `joker_transform` 一律拒绝，`_relic_card_value` 不调整 |
| RLC-06 | 反例 / 对手交互 | 变换后为 7-10/Q 可正常发动能力（来源 draw 合法） |
