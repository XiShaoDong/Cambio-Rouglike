# KONG — Cambio × 轻度 Roguelike（LAN MVP）

这是一个 Godot 4 的局域网可玩原型：一位玩家创建房间，其余 1–3 位玩家连接房主的局域网 IP。房主是规则权威，客户端只收到自己被允许查看的牌面，不能从普通同步状态读出其他暗牌。

## 已实现的 MVP

- 2–4 人 ENet 局域网房间，默认 UDP 端口 `7007`
- 54 张牌、开局查看下方两张、抽牌/弃牌堆替换
- 7/8、9/10、J、Q 的完整选择流程
- 弃牌后的 2.5 秒贴牌窗口、贴错罚抽、贴自己减牌、贴他人后交牌
- Kongbaya 终局、所有人最后一次行动、首回合冒险惩罚与三层比分判定
- 手牌牌面在结算前始终以背面显示；看牌以一次性弹窗呈现

## 本地运行

1. 用 **Godot 4.6** 导入本目录并运行项目。
2. 第一位玩家输入昵称，点击“创建房间”。
3. 其余玩家在同一局域网运行同一项目，输入房主的 IPv4 地址、昵称与端口后点击“加入房间”。
4. 房主在至少两人加入后点击“开始对局”。若连接失败，请允许系统防火墙的 UDP `7007` 入站连接。

可在同一台电脑上开两个 Godot 实例，用 `127.0.0.1` 验证流程。

## 开发者：本机双开测试

大厅里点击「开发者：本机双开测试」按钮，会自动启动第二个游戏实例并加入 `127.0.0.1` 当前端口；第二实例会自动确认开局记忆，之后两个窗口均可手动操作。

也可以手动双开：先运行一个实例建房，再执行：

```bash
godot --path . -- --dev-join 127.0.0.1:7007
```

自动化验证见 `tests/verify_net.tscn`（headless 双实例跑完整回合循环）。

## VPS 与 Roguelike 的扩展点

`scripts/core/game_state.gd` 是唯一裁定规则的服务器权威节点，UI 和 ENet 只提交命令。因此导出 Linux headless 包并在 VPS 启动该节点，就能替换当前“房主即服务器”的部署方式；规则和客户端协议无需改写。

`scripts/core/game_rules.gd` 的 `new_default_run()` 持有生命、遗物槽、遗物和 mutator ID；`scripts/core/run_modifier.gd` 是服务器侧事件钩子的基类。MVP 默认不启用它们，建议后续先做“每局开始三选一遗物 / 单局规则变体”，避免在基础的记忆与贴牌节奏稳定前引入永久成长和复杂数值。

## 规则取舍

“贴别人的牌”原文在“是否再收到一张对方牌”上有一句自相矛盾。此实现采用其中明确的操作顺序：贴中的目标牌进入弃牌堆，贴牌者选择自己一张牌交给目标玩家，因此贴牌者减少一张手牌。这个行为也与“贴牌可降低自己牌数”的核心目标一致。
